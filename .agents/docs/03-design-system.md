# 设计系统

## 视觉方向

系统延续 PNX 官网的深色机器人团队气质，但业务页面强调信息密度、可读性和状态清晰。视觉可以使用细线、技术网格和克制的红色强调，禁止复制 RoboMaster 官方素材或使用大面积霓虹、粒子尾迹、强烈 3D 和圆润 SaaS 卡片。

## 设计令牌

### 颜色

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `color.bg` | `#050505` | 页面背景 |
| `color.surface` | `#0C0D0F` | 主容器、侧栏 |
| `color.surfaceRaised` | `#121419` | 卡片、弹窗 |
| `color.surfaceHover` | `#181B21` | 悬停状态 |
| `color.textPrimary` | `#F4F5F7` | 标题与正文 |
| `color.textSecondary` | `#A3A9B3` | 辅助信息 |
| `color.textMuted` | `#747B86` | 禁用和元数据 |
| `color.border` | `rgba(255,255,255,0.10)` | 普通边框 |
| `color.borderStrong` | `rgba(255,255,255,0.20)` | 强调边框 |
| `color.accent` | `#E32636` | 主操作、当前状态 |
| `color.accentHover` | `#FF3346` | 主操作悬停 |
| `color.success` | `#36B37E` | 成功、已提交 |
| `color.warning` | `#E5A83B` | 临近截止、等待文件校验 |
| `color.danger` | `#F05252` | 错误、危险操作 |
| `color.info` | `#4C9AFF` | 信息和链接 |

红色只用于主操作、当前导航和关键品牌识别，不同时承担错误状态。文本和背景组合必须达到 WCAG 2.1 AA 对比度。

### 字体

- 中文正文：`Noto Sans SC`, `PingFang SC`, `Microsoft YaHei`, sans-serif。
- 英文与数字：`Inter`。
- 展示标题：`Barlow Condensed`，仅用于页面大标题和赛事标题。
- 代码：`JetBrains Mono`。
- 正文默认 16 px/1.7；数据表 14 px/1.5；辅助文本不小于 12 px。

### 尺寸

- 内容最大宽度：1440 px；普通阅读正文最大宽度：820 px。
- 间距采用 4 px 基线：4、8、12、16、24、32、48、64。
- 圆角：输入框和按钮 4 px，卡片 4 px，标签 2 px，弹窗最大 6 px。
- 阴影只用于弹窗和浮层；普通卡片依赖背景与边框分层。

## 页面骨架

- 学生端：顶部导航 + 最大 1440 px 主内容；桌面详情页可采用 8/4 栅格放置正文和状态侧栏。
- 管理端：240 px 左侧栏 + 主工作区；低于 1024 px 时侧栏收为抽屉。
- 断点：移动端 `<768`，平板 `768–1023`，桌面 `>=1024`。
- 所有关键流程在 360 px 宽度下可完成，禁止只通过悬停暴露操作。

## 组件规范

### 按钮

- `Primary`：红底白字，每个操作区最多一个，用于提交、发布、标记等主动作。
- `Secondary`：深色表面和强边框，用于保存草稿、预览和次要动作。
- `Ghost`：无背景，用于返回、取消和行内操作。
- `Danger`：危险红，仅用于禁用、撤回、解散等需要确认的操作。
- 高度 40 px，移动端触控区域至少 44×44 px；加载时保持宽度、显示进度并禁用重复提交。

### 输入与表单

- 标签始终可见，不用占位符代替标签。
- 必填、帮助文本和错误文本紧邻字段；错误使用颜色、图标和文字共同表达。
- Markdown 编辑器提供编辑/预览切换，预览必须使用与详情页相同的清洗管线。
- 日期时间输入显示 `Asia/Shanghai`，提交前回显完整日期、时间和时区。
- 保存草稿与正式发布/提交严格区分，正式操作使用确认摘要。

### 卡片、列表与表格

- 学生内容卡片突出状态、截止时间和单一下一步动作。
- 管理端优先使用表格；窄屏切换为字段标签明确的卡片。
- 可排序列显示方向；筛选条件以可移除标签展示；批量操作只在明确选择后出现。
- 空列表显示原因和下一步，不展示虚假示例数据。

### 状态标签

- 中性：草稿、归档、撤回。
- 信息：已发布、报名中、提交中。
- 成功：已验证、已激活、已提交、队伍有效。
- 警告：待邮箱验证、临近截止、邮件重试。
- 危险：禁用、拒绝、逾期、队伍无效、邮件最终失败。
- 标签文字使用面向用户的中文，不直接暴露数据库枚举。

### 弹窗与确认

- 删除、禁用、取消优秀标记、提前关闭和管理员修改锁定队伍必须确认。
- 确认弹窗说明影响对象、不可逆部分和后续恢复方式；需要原因的操作提供必填文本框。
- 普通信息使用非阻塞提示，不用弹窗替代页面级错误。

### 上传器

- 显示文件名、大小、分片进度、速度、剩余时间、校验状态和重试/终止操作。
- 浏览器刷新后通过上传会话恢复；已成功分片不重复上传。
- 正式提交前显示本版本附件合计和 2 GiB 上限。
- 上传成功不等于正式提交；两种状态在文案和颜色上明确区分。

### 时间与截止状态

- 大于 72 小时显示完整截止时间。
- 72 小时内同时显示相对时间和完整时间。
- 截止后使用“已截止”，若存在个人延期则明确显示“个人延期至”。
- 不用纯颜色表达紧迫程度。

## Markdown 正文

- 正文宽度不超过 820 px，标题层级从页面标题后的 `h2` 开始。
- 支持标题、段落、加粗、斜体、列表、引用、表格、链接、图片和代码块。
- 外链显示外部链接图标并使用 `rel="noopener noreferrer"`。
- 禁止原始 HTML、iframe 和可执行内容；代码块横向滚动，不撑破布局。
- 管理员预览、学生详情和邮件摘要使用一致的文本语义，邮件不直接发送完整私密 Markdown。

## 加载、空状态与错误

- 初次加载使用与最终布局一致的骨架屏，避免大幅跳动。
- 写操作显示局部进度；成功提示说明实际结果，例如“已发布，邮件正在后台发送”。
- 字段校验错误保留已填写内容并聚焦第一个错误。
- 页面级错误展示请求 ID、重试按钮和安全返回入口。
- 离线或网络中断时暂停上传并保留会话，不误报提交成功。

## 动效

- 持续 180–280 ms，允许淡入、轻微位移、线条展开和进度变化。
- 尊重 `prefers-reduced-motion`，关闭非必要位移与自动滚动。
- 禁止让动画延迟发布、提交、反馈和错误展示。

## 无障碍

- 所有交互可通过键盘完成，焦点顺序与视觉顺序一致。
- 焦点环使用 2 px 高对比描边，不因视觉美化移除。
- 弹窗、抽屉和菜单正确管理焦点并支持 Escape 关闭。
- 表格提供表头语义；图标按钮提供可读名称；状态变化通过 `aria-live` 适度播报。
- 上传进度使用 `progressbar` 语义；错误不能仅靠颜色区分。

## 需求映射

本设计系统支撑 NEWS-001、HW-001、SUB-001～SUB-004、COMP-001～COMP-004、SHOW-001～SHOW-005、FILE-001～FILE-007，以及 NFR-004、NFR-010、NFR-011。
