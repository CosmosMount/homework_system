# 页面规格

## 通用约定

- 所有业务页面在服务端确认 Session；未登录跳转 `/login`，不可见资源统一显示 404。
- 页面首次读取使用服务端数据，筛选、表单、上传和局部刷新使用客户端组件。
- 页面错误必须展示请求 ID；危险操作必须二次确认并在成功后刷新权威服务端数据。
- 每个列表提供加载、空、错误和分页状态；筛选写入 URL 查询参数。

## 全局登录后布局

- 所有学生和管理员业务页面使用共享响应式侧边栏；桌面端固定在左侧并可折叠，窄屏通过“打开主要导航”进入侧边抽屉。
- 当前路由在侧边栏中标记为 active；侧边栏只负责导航展示，所有页面和 API 权限仍由服务端鉴权。
- 个人资料、登录设备和退出操作位于侧边栏底部；学生未读通知数量在通知入口显示。
- 管理员真实角色为 `admin` 时，侧栏底部显示“查看学生视图”；开启后同一位置改为“返回管理员视图”。切换通过带 CSRF 的认证接口完成并刷新当前路由，学生视图只显示学生导航；服务端页面守卫仍按有效角色拒绝 `/admin/*`。

## 认证页面

### 登录 `/login`

- **目标**：为激活用户创建 Session；对应 AUTH-004、AUTH-006、AUTH-009。
- **组件**：用户名或校园邮箱、密码、显示密码、登录按钮、注册链接、忘记密码。
- **行为**：Connect 用户可以输入邮箱 `@` 前缀或完整邮箱，旧域名存量用户必须输入完整邮箱；成功后按持久化角色跳转。若该用户是系统唯一的已验证 active 账号，登录事务先保证其为管理员，再跳转管理概览。账号不存在、密码错误、待验证和禁用状态统一显示登录失败文案，不通过登录接口暴露账号状态。注册成功页和独立重发验证入口负责提示查收邮件。
- **异常**：429 显示重试时间；网络失败保留登录标识但清空密码。
- **移动端**：单列、无装饰侧栏，键盘弹出时主按钮仍可见。

### 注册 `/register`

- **目标**：创建 `@connect.hkust-gz.edu.cn` 学校邮箱账号；对应 AUTH-001～AUTH-003、AUTH-008、AUTH-010。
- **组件**：真实姓名、学号、校园邮箱、密码、确认密码、密码规则、隐私提示。
- **行为**：客户端即时提示格式，服务端精确校验 Connect 邮箱后缀和唯一性；成功后展示由邮箱前缀派生的用户名、查收邮件说明和“完成验证前不能登录”。验证成功即激活，空系统首个验证账号成为管理员，其余账号成为学生。
- **异常**：重复邮箱/学号使用字段错误；对“重新发送验证”接口不暴露账号是否存在。

### 邮箱验证与密码流程

- `/verify-email` 消费一次性令牌，成功后直接激活账号并提供登录入口；空系统首个激活账号由事务唯一授予管理员角色，过期时允许重新发送。
- `/forgot-password` 始终返回统一成功提示。
- `/reset-password` 验证令牌后设置新密码，成功撤销其他 Session 并跳转登录。
- 对应 AUTH-002～AUTH-005、AUTH-009。

## 学生工作台 `/dashboard`

- **目标**：把未读通知、待交作业和进行中赛事集中为可执行清单。
- **数据**：当前用户、未读数量、最近通知、按最早截止排序的作业、我的赛事/队伍。
- **组件顺序**：问候与身份标签、重要通知、近期截止、我的赛事。
- **空状态**：无任务时显示“当前没有待办”，仍保留通知与作业入口。
- **权限**：只返回当前受众和当前团队数据；对应 NEWS-005、HW-006、TEAM-006。
- **移动端**：所有模块单列，截止时间和主操作在首屏可见。

## 通知

### 列表 `/announcements`

- **目标**：查看与本人相关的已发布、未归档通知；对应 NEWS-003～NEWS-005、NEWS-008。
- **组件**：关键词搜索、未读筛选、置顶区、时间线式列表、分页。
- **卡片字段**：标题、摘要、发布时间、置顶标签、附件标记和已读状态。
- **行为**：打开详情后标记已读；批量全部已读需要确认当前筛选范围。

### 详情 `/announcements/[announcementId]`

- **数据**：标题、发布时间、更新标记、清洗后的正文、附件、受众描述和上下篇导航。
- **权限**：学生必须属于受众；管理员可以预览任意状态。
- **附件**：下载前请求授权地址；外部 URL 不直接暴露对象键。
- **错误**：非受众与不存在均为 404；对应 NEWS-001、NEWS-007、NEWS-008、FILE-005。

## 作业与个人提交

### 作业列表 `/assignments`

- **目标**：查看受众快照包含自己的作业；对应 HW-002、HW-003、HW-006。
- **筛选**：待提交、已提交、已截止、全部和关键词；受众由服务端限定。
- **卡片**：标题、技术方向标签、公共/个人截止时间、最新版本、评语未读和主操作。
- **排序**：未截止按有效截止时间升序，已截止按截止时间倒序。

### 作业详情 `/assignments/[assignmentId]`

- **目标**：阅读要求、查看本作业优秀作业并创建新版本；对应 HW-001、HW-004、HW-006、SUB-001～SUB-004、SHOW-001～SHOW-005、FILE-001～FILE-007。
- **主区**：说明、培训资料外链、提交要求、允许类型、Markdown 文本、链接输入、附件上传器，以及位于提交区之后的“优秀作业”区块。
- **侧栏**：状态、公共截止、个人延期、最新版本、附件合计、提交按钮。
- **正式提交**：先完成上传与校验，再显示确认摘要；确认后创建不可变版本并进入版本详情。
- **截止状态**：截止后表单只读；存在个人延期时使用个人时间。上传完成但未正式提交的文件不显示为已提交。
- **恢复**：刷新后使用上传会话 ID 恢复分片；表单文本仅保存在本地草稿，正式版本以服务端为准。
- **优秀作业**：只列出本作业被管理员标记的版本，显示提交者姓名、文本、链接和授权附件；不显示私密评语或其他版本。

### 版本与评语 `/assignments/[assignmentId]/submissions/[submissionId]`

- **目标**：查看个人版本历史和私密评语；对应 SUB-003、SUB-005～SUB-008。
- **组件**：最新版本摘要、版本切换、文本/链接/附件清单、提交时间、对应评语、创建新版本入口。
- **权限**：仅提交所有者和管理员；学生不能删除、修改或比较他人版本。
- **空反馈**：显示“管理员尚未反馈”，不显示评分占位。

### 优秀作业详情 `/assignments/[assignmentId]/excellent-submissions/[versionId]`

- **目标**：在作业上下文中阅读一份优秀作业；对应 SHOW-001～SHOW-005。
- **数据**：作业标题、提交者姓名、被标记版本的文本、链接、附件和标记时间。
- **权限**：当前学生必须属于该作业受众；管理员始终可查看。版本未被标记、已取消标记或属于赛事时返回 404。
- **隐私**：不请求或渲染私密评语、内部审计和源提交的其他版本。

## 赛事与队伍

### 赛事列表 `/competitions`

- **目标**：查看已发布赛事和自己的报名/队伍状态；对应 COMP-001～COMP-003。
- **筛选**：报名中、提交中、已结束、全部。
- **卡片**：赛事名、阶段、关键时间、队伍人数范围、我的状态和下一步操作。

### 赛事详情 `/competitions/[competitionId]`

- **目标**：阅读校内赛公告、报名并进入队伍；对应 COMP-001～COMP-003、COMP-006、TEAM-001～TEAM-005。
- **模块**：赛事公告、时间轴、规则链接、报名状态和我的队伍摘要。
- **报名期**：未报名显示报名按钮；已报名且无队伍显示创建队伍和输入邀请码。
- **报名结束后**：展示队伍锁定状态；无效/取消资格队伍显示联系管理员说明。
- **个人取消资格**：仅被取消资格的本人显示管理员填写的个人原因；其他学生不得读取该原因。若其仍在队内，队伍只显示不泄露个人原因的通用取消资格说明。
- **归档**：所有操作只读，不展示排名区域。

### 我的队伍 `/competitions/[competitionId]/team`

- **目标**：完成建队、邀请、成员与队长管理；对应 TEAM-001～TEAM-007。
- **组件**：队伍名、状态、人数要求、成员列表、队长标记、邀请码操作和审计后的管理员变更提示。
- **队长操作**：轮换邀请码、移除成员、转让队长、解散队伍；锁定后全部隐藏。
- **成员操作**：报名期退出；队长未转让时不能退出。
- **并发冲突**：加入已满或已加入其他队伍时显示 409 对应的明确恢复路径。

## 个人资料

### `/profile`

- 展示姓名、学号、学校邮箱、可选技术方向和账号状态；未设置方向时明确显示“未设置”。
- 管理员可以在本页维护自己的姓名、学号和校园邮箱；修改邮箱会撤销当前 Session 并要求重新验证。学生不能自行修改学号、学校邮箱、技术方向或角色。届次不再展示或编辑。
- 管理员处于学生视图时按学生界面展示只读资料，不显示管理员资料编辑器；返回管理员视图后恢复编辑入口。真实角色降级导致 Session 撤销后，页面必须回到登录流程，不提供恢复管理员的客户端操作。
- 修改邮箱需要管理员操作并重新验证；对应 AUTH-007、AUTH-010。

### `/profile/sessions`

- 展示当前和其他 Session 的创建时间、最近活动、IP 摘要和设备摘要。
- 用户可以撤销其他 Session，不能在未确认时撤销当前请求上下文；对应 AUTH-006。

## 管理后台

### 概览 `/admin/dashboard`

展示未验证账号数量、未来 72 小时截止作业、无效队伍、最终失败邮件、近期审计和存储容量告警。每个指标链接到已带筛选条件的对应列表。

### 用户与方向

- `/admin/users` 支持状态、方向和角色过滤，以及禁用、恢复、方向维护和 `student/admin` 角色调整；初始管理员使用同一界面，不提供注册批准、拒绝或重开审核。
- `/admin/categories` 仅管理技术方向名称、编码和启用状态；历史届次记录不再提供产品入口，数据库与旧 API 暂保留。
- 对应 AUTH-007、AUTH-008、AUTH-010。
- `/admin/sessions` 仅管理员可见，展示当前活跃登录人员、角色、设备摘要、IP 网段和最近活动时间，不返回 Cookie 或 Session 令牌。

### 通知管理

- 列表显示状态、受众、发布时间、预计/实际接收数和邮件结果。
- 创建/编辑页包含 Markdown、附件、受众构建器、发布计划、置顶和邮件开关。
- 发布确认展示接收人数；更新提醒是独立动作，避免编辑即群发。
- 对应 NEWS-001～NEWS-007、MAIL-002～MAIL-005。

### 作业与提交管理

- 作业表单包含可编辑的 Markdown 说明、受众、外部资料、附件规则、发布时间和截止时间；已保存说明使用与学生详情相同的服务端安全 HTML 展示，不呈现内部实现标签。
- 作业详情展示受众快照和提交统计，可为个人延期。
- `/admin/submissions/[submissionId]` 展示版本并写私密评语；作业版本可直接标记或取消“优秀作业”，赛事版本不显示该操作。
- 对应 HW-001～HW-007、SUB-006～SUB-008、SHOW-001～SHOW-005。

### 赛事与队伍管理

- `/admin/competitions/[competitionId]` 的赛事表单定义校内赛公告、阶段时间和人数限制，并展示个人报名记录与队伍状态。
- 管理员可对个人报名执行带原因的取消资格；原因只对管理员和该学生本人可见，学生不能重新报名，仍在有效队伍时整队同步取消资格但仅显示通用团队原因。
- `/admin/competitions/[competitionId]/teams/[teamId]` 展示成员，允许带原因的补录、移除、队长变更、人数豁免和取消资格；所有操作审计。
- 管理员移除成员导致已锁队伍低于最低人数时自动转为 `invalid`；补录达标或人数豁免可恢复为 `locked`。
- 历史赛事提交详情按兼容接口只读；新赛事不创建作品提交或评语。
- 对应 COMP-001～COMP-006、TEAM-004～TEAM-005。

### 邮件与审计

- `/admin/mail` 展示 Outbox 状态、事件类型、接收方掩码、尝试次数、下次重试、最终错误和人工重试。
- `/admin/audit` 按操作者、动作、资源、请求 ID 和时间过滤，只读且不提供删除。
- 对应 MAIL-002～MAIL-005、NFR-006。

## 页面与 API 的数据边界

- 页面不得直接拼接 MinIO URL，必须通过上传和下载 API 获取短时授权地址。
- 管理端“查看学生视图”不模拟学生身份；需要验证受众时使用服务端预览结果。
- 前端可以缓存列表读取，但完成写操作后必须使相关缓存失效并重新读取服务端状态。
- 密码、一次性令牌、邀请明文和私密评语不进入客户端持久化状态、日志或分析事件。
