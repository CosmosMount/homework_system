# 认证、安全与邮件

## 安全目标

保护学生身份信息、私密提交与评语，保证管理员操作可追溯，并让对象存储、数据库和 SMTP 凭证不暴露到浏览器或用户网络。所有安全控制以服务端为准，对应 AUTH-001～AUTH-013、MAIL-001～MAIL-005、NFR-001～NFR-002、NFR-006～NFR-009、NFR-011～NFR-012。

## 密码

- 使用 Argon2id；参数在首次实现时以部署服务器基准测试选择，使单次校验约 200–500 ms，并把算法参数编码在哈希中。
- 密码最少 8 个字符，最多 128 个 Unicode 字符；允许密码管理器生成的空格和符号，不使用强制大小写组合规则。
- 拒绝常见泄露密码和与邮箱、学号高度相似的密码；错误只反馈规则，不记录原文。
- 禁止 MD5、SHA-1、普通 SHA-256、可逆加密或明文存储密码。
- 登录成功时若参数低于当前基线，透明重哈希。
- 修改或重置密码后撤销该用户其他 Session，并发送不含敏感信息的安全提醒邮件。

## 学校邮箱与直接激活

- 公开注册只接受规范化后满足 `^[^@]+@connect\.hkust-gz\.edu\.cn$` 的邮箱，不接受旧域名、子域、相似后缀或包含式匹配。
- Connect 邮箱的 local-part 自动作为派生用户名，不另存用户名。登录输入不含 `@` 时补全当前 Connect 域名；输入包含 `@` 时按完整邮箱规范化，旧域名存量账号因此只能用完整邮箱登录。
- 注册接口同时校验邮箱、学号唯一性；数据库唯一约束处理并发注册。驱动层包装的唯一冲突必须按受信任约束名映射为字段级 `400 VALIDATION_ERROR`，不得解析异常文本、泄露 SQL 或转为通用 500。
- 邮箱验证成功后在同一事务中把账号直接置为 `active`；事务先获取固定 advisory lock，系统此前无激活用户时授予 `admin`，否则保持 `student`。历史唯一的已验证 `active student` 在部署修正或下次成功登录时共用该锁持久化为管理员、撤销旧 Session 并审计；待验证、禁用或存在其他账号时不得提升。
- 初始管理员与后续管理员使用同一角色管理接口；可以维护技术方向、调整其他人员角色或禁用异常账号，方向为空不影响 Session 创建。届次字段仅保留历史兼容。
- 管理员修改邮箱后立即撤销 Session、清除 `email_verified_at` 并发送新验证邮件。

## 一次性令牌

- 使用密码学安全随机源生成至少 32 字节随机值；URL 使用无填充 Base64URL。
- 数据库只保存令牌 SHA-256 哈希、用途、用户、过期时间和使用时间。
- 异步邮件所需的令牌在业务事务内使用独立 Outbox 密钥认证加密；数据库和日志均不保存明文令牌，Worker 只在发送时于内存中解密。
- 邮箱验证令牌有效 24 小时；密码重置令牌有效 30 分钟。
- 令牌成功消费、密码变更或签发新令牌后，旧令牌不可再用。
- 确认接口在事务中锁定令牌行，防止并发重复消费。
- URL 令牌不得进入应用日志、分析平台或 Referer；确认页面设置 `Referrer-Policy: no-referrer`。

## 问卷二维码 token

- 问卷二维码 token 使用至少 24 字节密码学安全随机值，URL 使用 Base64URL；数据库只保存 SHA-256，管理员重新生成时在锁定问卷行后替换哈希，使旧码立即失效。
- token 只定位一份当前可开放访问的问卷，不代表用户身份或填写授权；问卷关闭期间 token 不可用于学生读取，重新开启不会轮换 token，原 token 仅在状态重新为 `open`、原时间窗口有效且未被管理员重新生成替换时恢复定位能力。`/intentions/[surveyId]` 和对应 API 始终验证 Session、有效角色、开放状态、填写时间窗口和剩余提交次数。
- 未登录扫码通过经允许列表校验的同源 `next` 跳转登录，拒绝外部 URL、`//host` 和 `/login` 递归；登录后返回原问卷与 token。
- 二维码由前端本地库生成，不把填写 URL 或 token 发送给第三方服务；token 不进入日志、审计、分析事件或客户端持久化状态。

## Session

- 生产 Cookie 名为 `__Host-pnx_session`，属性为 `Secure; HttpOnly; SameSite=Lax; Path=/`，不得设置 `Domain`。本地 HTTP 开发使用 `pnx_session` 且不得进入生产配置；未勾选“记住登录状态”时不得设置 `Max-Age/Expires`，浏览器关闭后清除。
- Cookie 只保存高熵随机令牌；数据库存令牌哈希和 Session 元数据。密码只在登录请求内存中短暂存在并由 Argon2id 校验，不写入 Cookie、localStorage、sessionStorage 或可逆字段。
- 普通会话按学生空闲 12 小时、管理员空闲 4 小时、绝对 14 天过期。主动记住会话的 Session/CSRF Cookie、空闲期与绝对期均最长 30 天；每次受保护请求只在绝对期内按节流策略更新最近活动时间。
- 记住会话使用 `HMAC-SHA256(raw_session_token, canonical_exact_client_ip)` 形成 `ip_binding_hash`；数据库不保存精确 IP。每次认证先由受控 Nginx 覆盖外部转发头，再同时验证 Cookie、账号状态、期限/撤销和精确 IP HMAC；IP 变化立即撤销。相同 IP 不能用于查询账号、选择 Session 或替代 Cookie。
- 登录后轮换 Session；角色变化、邮箱变化、密码重置、账号禁用和管理员主动撤销立即失效。
- Session 列表只显示是否已记住、IP 网段摘要和清洗后的设备摘要，不返回 token、绑定 HMAC 或精确 IP，也不保存完整浏览器指纹。
- 服务端渲染只能向内部 API 转发当前请求 Cookie 和经受控 Nginx 覆盖清洗的单值 `X-Forwarded-For`；缺失来源 IP 时不得自行伪造，也不得把 Session、精确 IP 或绑定值写入页面 HTML、客户端 JavaScript 或缓存键。

## CSRF 与同源策略

- 所有 `POST`、`PUT`、`PATCH`、`DELETE` 请求要求 `X-CSRF-Token`，值与 `__Host-pnx_csrf` Cookie 和 Session 内哈希匹配。
- 生产 CSRF Cookie 名为 `__Host-pnx_csrf`，属性为 `Secure; SameSite=Lax; Path=/`，可被同源前端读取，但不能包含 Session 信息；本地 HTTP 开发使用 `pnx_csrf`。其浏览器会话/持久生命周期必须与当前 Session 类型一致，轮换 CSRF 时不得把普通 Cookie 意外升级为持久 Cookie，也不得超过 Session 绝对期限。
- 登录、注册和密码申请没有现有 Session，仍校验 `Origin`/`Referer` 是否为配置的应用源，并接受 Nginx 的同源限制。
- CORS 生产配置只允许应用自身 Origin，不允许通配源和凭证组合。
- 状态变化不允许使用 GET；预签名 URL 只能执行指定对象、方法、分片和短期校验头。

## 授权

- 后端依赖先验证 Session、账号 `active` 状态和角色，再由业务 Service 检查资源关系。
- 学生通知/作业按受众或受众快照授权；不可见资源返回 404。
- 通知与作业 DELETE 只允许真实管理员且未开启学生视图，并要求 CSRF。未发布物理删除、已发布归档标记删除和手工归档后的首次删除都必须在包含删除行的资源锁事务中写脱敏审计；常规管理列表/详情从服务端排除删除标记，学生列表、详情、优秀作业和优秀附件签名继续排除归档资源，不能只依赖前端隐藏。重复 DELETE 只返回 204，不重复审计。
- 学生问卷只返回开放且处于时间窗口内的问卷和本人最新回答/提交次数；分题统计不含个人身份。完整管理问卷详情、草稿修改、状态转换和实名名单接口只允许真实管理员且未开启学生视图的 Session，状态写入继续要求 CSRF；管理详情不含个人回答，名单字段限于需求规定的身份、最新答案、补充说明、累计次数和最后提交时间。管理员学生视图按本人学生有效角色填写，不因此获得管理详情、重新开启权限或其他学生回答。
- 学生本人反馈答疑列表和详情必须在查询条件中绑定 `created_by == current_user.id`，他人记录与不存在统一返回 404；普通管理员视图不得调用学生创建/本人读取接口，管理员学生视图只按本人账号使用学生路径。公开答疑接口仍要求有效 Session，只允许读取 `question + resolved`，仓储查询不得连接用户表，响应不得包含提问者 UUID、姓名、学号、邮箱；开放问题、系统反馈和不存在统一 404。全部工单、提交学生身份、答复和 DELETE 接口只允许真实管理员且未开启学生视图的 Session；DELETE 还要求 CSRF、行锁和前端二次确认，不能只隐藏页面内容。本人详情只返回当前账号当前工单的未读提醒 ID，浏览器必须经受 CSRF 保护的单条已读接口更新；不得通过详情 GET 隐式写入或批量清除其他工单提醒。管理员删除事务只把目标工单的未读提醒标为已读，并以物理删除让本人、管理和公开查询同时不可见。
- 作业提交必须验证 `owner_user_id == current_user.id` 和有效截止时间。
- 赛事提交必须验证当前用户是有效锁定队伍的当前队长；团队成员只能读本队版本和评语。
- 个人参赛取消资格原因仅返回该学生本人和管理员；若联动取消队伍资格，队友只能读取固定通用团队原因，不能反推出个人原因。
- 文件下载先从通知、版本或作业内优秀标记关系反查业务权限，不能仅检查上传人。
- 管理员可以管理业务，但不能通过学生接口代交正式版本；高风险管理动作必须填写原因并审计。
- 管理员补录、移除成员后必须重新计算锁定队伍人数有效性；状态变化和原因写入审计，但邀请码明文、个人取消资格原因不得进入面向队友的响应。
- `DELETE /admin/teams/{team_id}` 只允许真实管理员且未开启学生视图，要求同源、CSRF、非空内部原因和前端二次确认；后端必须先锁定队伍和当前成员，再以团队提交引用决定物理删除或保留 `dissolved` 壳。两种模式都释放一赛一队占用并从学生/常规管理员读取隐藏；有历史提交时不得删除版本、评语、附件或暴露原成员身份。
- 禁止撤销系统中最后一个激活管理员的管理员角色或禁用该账号；用户表恰好只有一个已验证 active 账号时必须保证其为管理员。“初始管理员”不形成不可转移的第三种角色。

### 账号永久删除与本人注销

- `DELETE /admin/users/{user_id}` 只允许真实管理员且未开启学生视图，不能删除当前操作者；`DELETE /auth/account` 只删除当前 Session 所属账号。两者均要求有效 Session、同源、CSRF、当前密码重新认证，以及规范化后与目标账号完全一致的邮箱确认。
- 管理员删除还要求至少 3 个非空白字符的内部原因和显式 PostgreSQL + MinIO 可恢复备份确认；该确认只是一道人为防误操作门，不会替代真实备份。用户本人注销不要求管理备份确认，但页面必须披露操作不可撤销以及备份保留期边界。
- 两条路径共用管理员生命周期 advisory lock，先锁定目标一次性令牌、Session、用户、队伍、文件和相关任务后再次校验。管理员不能通过管理接口删除自己，最后一个激活管理员无论由他人删除还是本人注销都返回业务冲突。
- PostgreSQL 在同一事务物理删除账号、Session、令牌和个人数据；平台通知、作业、赛事、问卷、知识库同步运行、团队提交及其他共享记录继续保留，并把已删除创建者、操作者或上传者字段置空。目标为队长时必须先转给最早加入的其他当前成员；无人可转时解散队伍，锁定队伍删员后低于最小人数且无豁免时转为失效。
- 个人作业提交及其版本可随账号擦除级联删除；正式版本不可变触发器只在当前事务显式设置 `pnx.account_erasure=on` 且父提交行已经不存在时允许该 DELETE，普通 UPDATE/DELETE 继续以 `55000` 拒绝。
- PostgreSQL 与 MinIO 没有跨系统事务。个人对象键和 multipart 标识在数据库事务中进入可靠 `delete_account_object` Outbox；Worker 必须先幂等终止 multipart 再删除对象。Worker 暂停时数据库删除仍可提交，对象不可再经业务授权读取，待 Worker 恢复后继续清理；最终失败必须告警并人工处理，禁止按桶扫描猜测删除。
- 目标邮件任务只在既有邮件类型内匹配当前邮箱、目标 UUID 事件键和该用户一次性令牌事件键；收件人/姓名与加密秘密清空，活动任务转为 `dead/USER_DELETED`。认证安全事件保留攻击分析时间与来源维度，但清空目标用户 UUID 和规范化邮箱。
- 成功与业务拒绝都写脱敏审计。成功仅记录目标 UUID、调用模式、原角色/状态、管理原因、删除计数及队伍/对象任务计数；禁止记录确认邮箱、密码、姓名、学号、文件名、对象键、multipart 标识、问卷答案、提交/工单正文。自助注销使用固定原因，不把用户输入写入审计。

## 限流与防暴力登录

应用层先把用户名或完整邮箱统一规范化为账号邮箱，查询账号并执行真实或 dummy Argon2id 校验。已验证 `active` 账号的正确密码直接进入 Session 事务；只有账号不存在、密码错误或状态不可登录时，才以规范化邮箱和 IP 网段的近期 `auth_security_events` 计数并追加当前失败，因此 Connect 用户名与对应完整邮箱不能拆分失败限流。注册、验证邮件重发和密码重置申请只写安全分析事件，不读取历史事件形成持久等待。Nginx 另设粗粒度连接与请求限速：

| 操作 | 邮箱限制 | IP 限制 |
| --- | ---: | ---: |
| 登录失败 | 10 分钟内 5 次 | 10 分钟内 30 次 |
| 注册 | 无应用层持久窗口 | 无应用层持久窗口 |
| 重发验证 | 无应用层持久窗口 | 无应用层持久窗口 |
| 申请重置 | 无应用层持久窗口 | 无应用层持久窗口 |
| 输入队伍邀请码 | 15 分钟内 10 次 | 15 分钟内 60 次 |

- 无效登录达限返回 429 和 `Retry-After: 600`；10 分钟计数窗口结束后自动恢复。已验证 `active` 账号的正确密码不进入应用层持久等待，但仍可能受 Nginx 瞬时请求桶限制。
- 注册、重发验证和申请重置的既有安全事件不删除，也不再触发应用层 429；这些入口仍受 Nginx 瞬时请求桶限制。
- 成功登录不删除、清空或改写安全事件，也不批量重算密码哈希；仅编码参数低于当前 Argon2id 基线时保留透明重哈希。
- 响应时间和文案尽量统一，避免通过重置、验证重发或登录枚举账号。
- `pending_email` 即使密码正确也必须与错误密码一样失败；用户名登录不得绕过邮箱验证。注册成功页和登录页可以主动说明验证要求，统一失败响应也可以把验证列为通用排查项，但不得确认当前标识是否存在或处于何种状态。

## Markdown 与链接安全

- 服务端将 Markdown 转换为允许列表 HTML并存缓存；客户端不直接渲染原始 Markdown HTML。
- 禁止原始 HTML、`script`、`iframe`、`object`、`embed`、SVG、事件属性、内联样式和 `javascript:`/`data:` 协议。
- 外链仅允许 `https` 和必要的 `http` 校内地址；渲染时添加 `rel="noopener noreferrer nofollow"`。
- Markdown 图片首版只允许已授权附件，不允许任意远程图片自动加载，避免跟踪和混合内容。
- 代码块以文本转义，不执行 Mermaid 或其他浏览器脚本扩展。
- 反馈答疑原文和管理员答复都走同一清洗器；公开答疑只能输出已保存的安全 HTML，不输出 Markdown 源文或身份字段。站内通知、审计、普通日志和分析事件不得包含问题或答复正文；创建/答复审计只记录工单 UUID、类型、状态、revision 与必要的安全标题，删除审计不得记录标题、提交者身份、正文或答复，只记录工单 UUID、类型、原状态、revision 和 `physical` 模式。

## 文件安全

- 全局白名单默认允许常见文档、图片、视频、压缩包、源码文本和机器人设计文件；明确禁止可执行程序、脚本安装包、HTML 和 SVG。精确清单写入部署配置并由任务规则收窄。
- 同时检查规范化扩展名、声明媒体类型、内容探测类型、实际大小和 SHA-256；名称仅作为显示值。
- 上传对象在校验完成前不可下载或关联版本。
- 下载使用 5 分钟预签名 URL，并通过 Nginx/MinIO 强制 HTTPS；对象键不含原文件名、学号或邮箱。
- 首版不自动执行上传内容，也不提供 Office/PDF 在线预览，从而降低恶意文件风险。
- 校内场景首版不内置恶意软件扫描服务；部署文档必须记录此剩余风险，用户下载后由终端安全软件继续防护。

## HTTP 安全头

Nginx至少设置：

- `Strict-Transport-Security`，在确认全站 HTTPS 后启用长期策略。
- `Content-Security-Policy`：默认同源，脚本使用 nonce，不允许内联脚本和对象，图片只允许同源对象路径。
- `X-Content-Type-Options: nosniff`。
- `Referrer-Policy: strict-origin-when-cross-origin`；令牌页面覆盖为 `no-referrer`。
- `Permissions-Policy` 禁用首版不使用的摄像头、麦克风、定位等能力。
- `frame-ancestors 'none'`，阻止系统被第三方 iframe 嵌入。

### 邮件类型

| 类型 | 内容原则 | 需求 |
| --- | --- | --- |
| 邮箱验证 | 一次性验证链接和过期时间 | AUTH-002、MAIL-001 |
| 密码重置 | 一次性重置链接和安全提示 | AUTH-005、MAIL-001 |
| 通知提醒 | 标题、摘要、站内详情链接，不含永久附件地址 | NEWS-006、MAIL-001 |
| 延期提醒 | 作业标题、新截止时间和站内链接 | HW-004、MAIL-001 |
| 问卷填写提醒 | 称呼、问卷标题和站内填写链接；只由真实管理员显式选择手动成员、一个技术组或全部激活学生触发 | INT-007、MAIL-001～MAIL-005 |
| 安全提醒 | 密码/邮箱变化和 Session 撤销提示 | AUTH-005、AUTH-010 |

私密评语默认只创建站内提醒；邮件仅提示“有新的反馈”，不包含正文或附件。

问卷邮件不会在问卷开放时自动群发，也不接受任意收件邮箱。真实管理员必须显式选择 `manual`、`direction` 或 `all`；服务端在发送事务内重新校验手动 UUID，或按当前激活技术组/全部激活学生解析权威成员集合，停用技术组和空集合整体拒绝。正文不得包含答案、补充说明、二维码 token、管理员身份或永久资源地址。

### SMTP

- 使用 STARTTLS 或 TLS，验证服务器证书；凭证只从部署密钥注入。
- 发件人、回复地址和应用基准 URL必须显式配置。
- 邮件模板在服务端渲染，HTML 与纯文本双格式；用户内容必须转义。
- 接收方地址仅来自服务端重新校验的已验证用户，不接受 API 任意传入地址；问卷邮件只从手动复核或服务端范围查询得到的当前激活学生读取学校邮箱。

### Outbox 与重试

- 业务事务写入唯一 `event_key` 的 `outbox_jobs`；Worker 使用 `FOR UPDATE SKIP LOCKED` 批量领取。
- 邮箱验证和密码重置任务只把非秘密模板变量写入普通 `payload`，令牌使用独立 `OUTBOX_ENCRYPTION_KEY` 认证加密；管理端永不返回 `secret_payload_ciphertext`。
- Worker 解密和连接 SMTP 前必须按事件键复核一次性令牌 ID、用途、未使用状态和有效期；已使用、过期、用途不符或已被后续签发替代的任务直接进入 `dead/TOKEN_SUPERSEDED`，不得调用 SMTP。
- 单任务最多尝试 8 次，退避间隔依次为 1 分钟、5 分钟、15 分钟、1 小时、4 小时、12 小时、24 小时、48 小时。
- SMTP 4xx 和网络错误重试；明确的永久地址错误直接进入 `dead`。所有错误摘要脱敏。
- Worker 在超出锁租约后允许其他实例重新领取；发送提供商若支持幂等标识则使用 `event_key`。
- 问卷邮件使用 `survey_id + survey_revision + recipient_user_id` 形成唯一事件键；三种范围最终按成员执行同一去重，同一开放周期的范围重叠只计入已存在任务，关闭后重新开启 revision 变化才允许再次显式入队。收件人解析/校验、Outbox 与脱敏审计必须同事务提交。
- 管理员人工重试复用原业务事件并创建新的执行尝试，不生成第二条站内通知。
- `delete_account_object` 不走 SMTP：普通载荷只保存服务端随机对象键，multipart 标识使用 Outbox 独立密钥认证加密；成功后同时清空普通和秘密载荷。对象存储瞬时失败沿用最多 8 次退避，错误摘要不得包含对象键或上传标识；坏载荷直接进入 `dead/INVALID_JOB_PAYLOAD`。

## 审计与日志脱敏

必须审计：初始管理员授予、账号禁用/恢复/角色变更/永久删除/本人注销、技术方向调整、通知发布/删除、作业发布/延期/删除、问卷邮件入队、赛事阶段变化、管理员修改或删除队伍、评语修订、优秀作业标记/取消、文件合规删除和最终失败邮件重试。问卷邮件审计只记录问卷 UUID、`recipient_scope`、技术组模式的 `direction_id` 与请求/新增/已存在数量，不记录收件成员 UUID、姓名、学号或邮箱；队伍删除审计只记录目标 UUID、原状态、`physical/dissolved_retained` 模式、释放人数、历史提交数量和内部原因，不记录成员身份、邀请码、提交正文、附件名或对象键；其他内容删除只记录目标 UUID、原状态和删除模式，账号删除遵守上节更严格的身份、确认信息和对象标识禁止项。

日志和审计禁止包含：密码、Session Cookie、CSRF 值、一次性令牌、完整邀请码、SMTP/MinIO 密钥、完整私密评语、问卷答案/补充说明和上传文件内容。邮箱在普通运维日志中掩码，审计目标使用用户 UUID；问卷提交审计只记录问卷 UUID 和累计提交次数。

## 密钥管理与轮换

- `.env.example` 只列变量名和安全说明，不含真实值。
- Session 签名/pepper 支持当前和前一把密钥，以便不中断轮换；新令牌只用当前密钥。
- Outbox 投递秘密使用独立的 32 字节认证加密密钥，不复用 Session、CSRF、数据库或 MinIO 凭证。
- SMTP、数据库和 MinIO 凭证至少每学年或在泄露怀疑时轮换。
- 备份文件单独加密，备份密钥与备份数据分开存放。

## 安全验证清单

- 账号枚举、登录暴力破解、Session 固定、CSRF、越权读取与写入，并发验证只能授予一个初始管理员，以及并发登录只能对唯一账号写一次管理员授予审计。
- 记住登录默认关闭且不持久化密码；普通 Cookie 无 `Max-Age`，持久 Cookie 最长 30 天；同一 Cookie/同一精确 IP 有效，不同 IP 立即撤销；相同 IP 无 Cookie 仍为 401，数据库、响应、会话列表与日志不含精确 IP 或绑定 HMAC。
- 学生访问他人提交、跨团队评语、非队长提交和直接对象键下载。
- Markdown XSS、危险链接、伪装扩展名、超限文件、重复分片与哈希不匹配。
- 管理员高风险动作缺少原因、备份确认、重新认证或目标邮箱确认；管理员删除自己、最后管理员被删除/注销、审计日志包含秘密。
- 近期活跃、待验证和禁用账号可按相同安全门删除；学生/管理员学生视图越权、CSRF 缺失、并发删除与队长转移/解散/失效不会留下半完成事务。
- 普通正式版本 UPDATE/DELETE 继续被触发器拒绝；只有账号擦除事务中父个人提交已删除时允许版本级联，伪造事务状态但父提交仍存在时也必须拒绝。
- SMTP 故障、Worker 重启和重复领取不会丢任务或重复创建站内通知；账号对象清理重复终止/删除幂等，失败不在日志暴露对象键或 multipart 标识。

## 账号删除上线前备份要求

- 开发与静态验证不得用当前运行 PostgreSQL 或 MinIO 试删账号，也不得为满足“尽量备份”而擅自运行会读取当前数据的备份脚本。
- 生产启用 `20260829_0015` 和删除入口前，必须由有权限的部署方新建并验证 PostgreSQL + MinIO 同一时间点的加密完整备份，至少核对归档权限、SHA-256、`pg_restore --list`、对象清单和异机保留。
- 账号删除成功后应用不能恢复目标账号。若必须恢复账号及个人对象，只能把删除前的同点备份恢复到隔离环境进行评估；不得直接覆盖当前生产库。执行过账号删除后应优先前滚修复，迁移降级会在已产生去标识空值时明确拒绝。

## 飞书知识库安全补充

- 目录、文档和媒体读取均要求有效 Session；管理状态与同步写操作要求真实管理员且未开启学生视图，写操作另校验同源和 CSRF。
- `FEISHU_APP_SECRET` 只从环境或 `FEISHU_APP_SECRET_FILE` 读取；tenant token 仅保存在当前 Worker 或首次上线内部同步进程的内存。数据库、响应、审计、结构化日志和错误摘要不得记录上述秘密或飞书响应正文。
- 飞书同步配置只接受 App ID、有效 App Secret 和 `FEISHU_WIKI_URL` 三项；URL 必须是 HTTPS 飞书/Lark 租户域名，路径只允许数字空间 ID 或受控文档 token，不接受用户信息、非标准端口和 fragment。
- 飞书客户端只构造 `https://open.feishu.cn/open-apis/*`，拒绝跨主机和重定向，分页、节点、文档、媒体大小与超时均有上限，避免 SSRF 与资源耗尽。
- 参考仓库提交 `c28f8a0` 只作为同步顺序、块转换和内容区排布契约；不得复制其硬编码租户域名、公开静态 token 文件名、浏览器公开访问或宽松链接协议。首次上线内部命令与 Worker 使用相同出站和脱敏边界。
- 飞书富文本只转换为受控结构，React 默认以文本转义；链接只保留带主机的 HTTPS，内部 mention 映射为当前快照文档，不渲染飞书任意 HTML。公式只从显式 `equation` 结构进入本地 KaTeX，同步时单公式最多保留 20,000 字符，渲染时设置 `trust=false`、限制宏展开和尺寸，并把 HTML 扩展作为硬错误；插入 DOM 的 HTML 只能来自该受限 KaTeX 生成器，解析失败显示转义后的 LaTeX 源文。
- 真实学生和管理员学生视图不渲染飞书原文、未映射飞书文档或附件失败回退链接；显式映射到当前成功快照的文档 mention 只形成站内切换。真实管理员普通视图可以保留正文来源回退用于排障。正文附件、富文本内嵌文件和目录独立文件都只能使用内部资源 UUID 路径，并在服务端证明其被最新成功快照的文档资源关联或 `file` 节点引用；目录文件失败时不得降级为飞书下载地址。
- 媒体 URL 只接受内部资源 UUID，并验证最新成功快照引用；对象键和飞书媒体 token 不下发。失败原因只使用稳定错误码与中文脱敏摘要。
