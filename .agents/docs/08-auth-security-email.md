# 认证、安全与邮件

## 安全目标

保护学生身份信息、私密提交与评语，保证管理员操作可追溯，并让对象存储、数据库和 SMTP 凭证不暴露到浏览器或用户网络。所有安全控制以服务端为准，对应 AUTH-001～AUTH-010、MAIL-001～MAIL-005、NFR-001～NFR-002、NFR-006、NFR-011～NFR-012。

## 密码

- 使用 Argon2id；参数在首次实现时以部署服务器基准测试选择，使单次校验约 200–500 ms，并把算法参数编码在哈希中。
- 密码最少 8 个字符，最多 128 个 Unicode 字符；允许密码管理器生成的空格和符号，不使用强制大小写组合规则。
- 拒绝常见泄露密码和与邮箱、学号高度相似的密码；错误只反馈规则，不记录原文。
- 禁止 MD5、SHA-1、普通 SHA-256、可逆加密或明文存储密码。
- 登录成功时若参数低于当前基线，透明重哈希。
- 修改或重置密码后撤销该用户其他 Session，并发送不含敏感信息的安全提醒邮件。

## 学校邮箱与直接激活

- 公开注册只接受规范化后满足 `^[^@]+@connect\.hkust-gz\.edu\.cn$` 的邮箱，不接受旧域名、子域、相似后缀或包含式匹配。
- Connect 邮箱的 local-part 自动作为派生用户名，不另存用户名。登录输入不含 `@` 时补全当前 Connect 域名；输入包含 `@` 时按完整邮箱规范化，旧域名存量账号因此只能用完整邮箱登录。
- 注册接口同时校验邮箱、学号唯一性；数据库唯一约束处理并发注册。
- 邮箱验证成功后在同一事务中把账号直接置为 `active`；事务先获取固定 advisory lock，系统此前无激活用户时授予 `admin`，否则保持 `student`。历史唯一的已验证 `active student` 在部署修正或下次成功登录时共用该锁持久化为管理员、撤销旧 Session 并审计；待验证、禁用或存在其他账号时不得提升。
- 初始管理员与后续管理员使用同一角色管理接口；可以维护技术方向、调整其他人员角色或禁用异常账号，方向为空不影响 Session 创建。届次字段仅保留历史兼容。
- 管理员修改邮箱后立即撤销 Session、清除 `email_verified_at` 并发送新验证邮件。

## 一次性令牌

- 使用密码学安全随机源生成至少 32 字节随机值；URL 使用无填充 Base64URL。
- 数据库只保存令牌 SHA-256 哈希、用途、用户、过期时间和使用时间。
- 异步邮件所需的令牌在业务事务内使用独立 Outbox 密钥认证加密；数据库和日志均不保存明文令牌，Worker 只在发送时于内存中解密。
- 邮箱验证令牌有效 24 小时；密码重置令牌有效 30 分钟。
- 令牌成功消费、密码变更或签发新令牌后，旧令牌不可再用。
- 确认接口在事务中锁定令牌行，防止并发重复消费。
- URL 令牌不得进入应用日志、分析平台或 Referer；确认页面设置 `Referrer-Policy: no-referrer`。

## 意向二维码 token

- 调查二维码 token 使用至少 24 字节密码学安全随机值，URL 使用 Base64URL；数据库只保存 SHA-256，管理员重新生成时在锁定调查行后替换哈希，使旧码立即失效。
- token 只定位一份未关闭调查，不代表用户身份或填写授权；`/intentions/[surveyId]` 和对应 API 仍必须验证 Session、有效角色、开放状态和填写时间窗口。
- 未登录扫码通过经允许列表校验的同源 `next` 跳转登录，拒绝外部 URL、`//host` 和 `/login` 递归；登录后返回原调查与 token。
- 二维码由前端本地库生成，不把填写 URL 或 token 发送给第三方服务；token 不进入日志、审计、分析事件或客户端持久化状态。

## Session

- 生产 Cookie 名为 `__Host-pnx_session`，属性为 `Secure; HttpOnly; SameSite=Lax; Path=/`，不得设置 `Domain`。本地 HTTP 开发使用 `pnx_session` 且不得进入生产配置。
- Cookie 只保存高熵随机令牌；数据库存令牌哈希和 Session 元数据。
- 学生空闲 12 小时过期，管理员空闲 4 小时过期，绝对有效期均为 14 天；每次受保护请求按节流策略更新最近活动时间。
- 登录后轮换 Session；角色变化、邮箱变化、密码重置、账号禁用和管理员主动撤销立即失效。
- Session 列表只显示 IP 网段摘要和清洗后的设备摘要，不保存完整浏览器指纹。
- 服务端渲染只能向内部 API 转发当前请求 Cookie，不得把 Session 写入页面 HTML、客户端 JavaScript 或缓存键。

## CSRF 与同源策略

- 所有 `POST`、`PUT`、`PATCH`、`DELETE` 请求要求 `X-CSRF-Token`，值与 `__Host-pnx_csrf` Cookie 和 Session 内哈希匹配。
- 生产 CSRF Cookie 名为 `__Host-pnx_csrf`，属性为 `Secure; SameSite=Lax; Path=/`，可被同源前端读取，但不能包含 Session 信息；本地 HTTP 开发使用 `pnx_csrf`。
- 登录、注册和密码申请没有现有 Session，仍校验 `Origin`/`Referer` 是否为配置的应用源，并接受 Nginx 的同源限制。
- CORS 生产配置只允许应用自身 Origin，不允许通配源和凭证组合。
- 状态变化不允许使用 GET；预签名 URL 只能执行指定对象、方法、分片和短期校验头。

## 授权

- 后端依赖先验证 Session、账号 `active` 状态和角色，再由业务 Service 检查资源关系。
- 学生通知/作业按受众或受众快照授权；不可见资源返回 404。
- 学生意向只返回开放调查和本人当前回答；管理员统计只能返回人数与比例，不得返回个人答案。管理员学生视图按本人学生有效角色填写，不因此获得其他学生回答。
- 作业提交必须验证 `owner_user_id == current_user.id` 和有效截止时间。
- 赛事提交必须验证当前用户是有效锁定队伍的当前队长；团队成员只能读本队版本和评语。
- 个人参赛取消资格原因仅返回该学生本人和管理员；若联动取消队伍资格，队友只能读取固定通用团队原因，不能反推出个人原因。
- 文件下载先从通知、版本或作业内优秀标记关系反查业务权限，不能仅检查上传人。
- 管理员可以管理业务，但不能通过学生接口代交正式版本；高风险管理动作必须填写原因并审计。
- 管理员补录、移除成员后必须重新计算锁定队伍人数有效性；状态变化和原因写入审计，但邀请码明文、个人取消资格原因不得进入面向队友的响应。
- 禁止撤销系统中最后一个激活管理员的管理员角色或禁用该账号；用户表恰好只有一个已验证 active 账号时必须保证其为管理员。“初始管理员”不形成不可转移的第三种角色。

## 限流与防暴力登录

应用层先把用户名或完整邮箱统一规范化为账号邮箱，再以该邮箱和 IP 网段的近期 `auth_security_events` 计数；因此 Connect 用户名与对应完整邮箱不能拆分限流。Nginx 另设粗粒度连接与请求限速：

| 操作 | 邮箱限制 | IP 限制 |
| --- | ---: | ---: |
| 登录失败 | 15 分钟内 5 次 | 15 分钟内 30 次 |
| 注册 | 不适用 | 1 小时内 5 次 |
| 重发验证 | 1 小时内 3 次 | 1 小时内 20 次 |
| 申请重置 | 1 小时内 3 次 | 1 小时内 20 次 |
| 输入队伍邀请码 | 15 分钟内 10 次 | 15 分钟内 60 次 |

- 达限返回 429 和 `Retry-After`；计数窗口结束后自动恢复。
- 成功登录不删除安全事件，但新的失败窗口只统计当前时间范围。
- 响应时间和文案尽量统一，避免通过重置、验证重发或登录枚举账号。
- `pending_email` 即使密码正确也必须与错误密码一样失败；用户名登录不得绕过邮箱验证。注册成功页和登录页可以主动说明验证要求，统一失败响应也可以把验证列为通用排查项，但不得确认当前标识是否存在或处于何种状态。

## Markdown 与链接安全

- 服务端将 Markdown 转换为允许列表 HTML并存缓存；客户端不直接渲染原始 Markdown HTML。
- 禁止原始 HTML、`script`、`iframe`、`object`、`embed`、SVG、事件属性、内联样式和 `javascript:`/`data:` 协议。
- 外链仅允许 `https` 和必要的 `http` 校内地址；渲染时添加 `rel="noopener noreferrer nofollow"`。
- Markdown 图片首版只允许已授权附件，不允许任意远程图片自动加载，避免跟踪和混合内容。
- 代码块以文本转义，不执行 Mermaid 或其他浏览器脚本扩展。

## 文件安全

- 全局白名单默认允许常见文档、图片、视频、压缩包、源码文本和机器人设计文件；明确禁止可执行程序、脚本安装包、HTML 和 SVG。精确清单写入部署配置并由任务规则收窄。
- 同时检查规范化扩展名、声明媒体类型、内容探测类型、实际大小和 SHA-256；名称仅作为显示值。
- 上传对象在校验完成前不可下载或关联版本。
- 下载使用 5 分钟预签名 URL，并通过 Nginx/MinIO 强制 HTTPS；对象键不含原文件名、学号或邮箱。
- 首版不自动执行上传内容，也不提供 Office/PDF 在线预览，从而降低恶意文件风险。
- 校内场景首版不内置恶意软件扫描服务；部署文档必须记录此剩余风险，用户下载后由终端安全软件继续防护。

## HTTP 安全头

Nginx至少设置：

- `Strict-Transport-Security`，在确认全站 HTTPS 后启用长期策略。
- `Content-Security-Policy`：默认同源，脚本使用 nonce，不允许内联脚本和对象，图片只允许同源对象路径。
- `X-Content-Type-Options: nosniff`。
- `Referrer-Policy: strict-origin-when-cross-origin`；令牌页面覆盖为 `no-referrer`。
- `Permissions-Policy` 禁用首版不使用的摄像头、麦克风、定位等能力。
- `frame-ancestors 'none'`，阻止系统被第三方 iframe 嵌入。

## 邮件设计

### 邮件类型

| 类型 | 内容原则 | 需求 |
| --- | --- | --- |
| 邮箱验证 | 一次性验证链接和过期时间 | AUTH-002、MAIL-001 |
| 密码重置 | 一次性重置链接和安全提示 | AUTH-005、MAIL-001 |
| 通知提醒 | 标题、摘要、站内详情链接，不含永久附件地址 | NEWS-006、MAIL-001 |
| 延期提醒 | 作业标题、新截止时间和站内链接 | HW-004、MAIL-001 |
| 安全提醒 | 密码/邮箱变化和 Session 撤销提示 | AUTH-005、AUTH-010 |

私密评语默认只创建站内提醒；邮件仅提示“有新的反馈”，不包含正文或附件。

### SMTP

- 使用 STARTTLS 或 TLS，验证服务器证书；凭证只从部署密钥注入。
- 发件人、回复地址和应用基准 URL必须显式配置。
- 邮件模板在服务端渲染，HTML 与纯文本双格式；用户内容必须转义。
- 接收方地址仅来自已验证用户，不接受 API 任意传入地址。

### Outbox 与重试

- 业务事务写入唯一 `event_key` 的 `outbox_jobs`；Worker 使用 `FOR UPDATE SKIP LOCKED` 批量领取。
- 邮箱验证和密码重置任务只把非秘密模板变量写入普通 `payload`，令牌使用独立 `OUTBOX_ENCRYPTION_KEY` 认证加密；管理端永不返回 `secret_payload_ciphertext`。
- Worker 解密和连接 SMTP 前必须按事件键复核一次性令牌 ID、用途、未使用状态和有效期；已使用、过期、用途不符或已被后续签发替代的任务直接进入 `dead/TOKEN_SUPERSEDED`，不得调用 SMTP。
- 单任务最多尝试 8 次，退避间隔依次为 1 分钟、5 分钟、15 分钟、1 小时、4 小时、12 小时、24 小时、48 小时。
- SMTP 4xx 和网络错误重试；明确的永久地址错误直接进入 `dead`。所有错误摘要脱敏。
- Worker 在超出锁租约后允许其他实例重新领取；发送提供商若支持幂等标识则使用 `event_key`。
- 管理员人工重试复用原业务事件并创建新的执行尝试，不生成第二条站内通知。

## 审计与日志脱敏

必须审计：初始管理员授予、账号禁用/恢复/角色变更、技术方向调整、通知发布、作业发布/延期、赛事阶段变化、管理员修改锁定队伍、评语修订、优秀作业标记/取消、文件合规删除和最终失败邮件重试。

日志和审计禁止包含：密码、Session Cookie、CSRF 值、一次性令牌、完整邀请码、SMTP/MinIO 密钥、完整私密评语和上传文件内容。邮箱在普通运维日志中掩码，审计目标使用用户 UUID。

## 密钥管理与轮换

- `.env.example` 只列变量名和安全说明，不含真实值。
- Session 签名/pepper 支持当前和前一把密钥，以便不中断轮换；新令牌只用当前密钥。
- Outbox 投递秘密使用独立的 32 字节认证加密密钥，不复用 Session、CSRF、数据库或 MinIO 凭证。
- SMTP、数据库和 MinIO 凭证至少每学年或在泄露怀疑时轮换。
- 备份文件单独加密，备份密钥与备份数据分开存放。

## 安全验证清单

- 账号枚举、登录暴力破解、Session 固定、CSRF、越权读取与写入，并发验证只能授予一个初始管理员，以及并发登录只能对唯一账号写一次管理员授予审计。
- 学生访问他人提交、跨团队评语、非队长提交和直接对象键下载。
- Markdown XSS、危险链接、伪装扩展名、超限文件、重复分片与哈希不匹配。
- 管理员高风险动作缺少原因、最后管理员被撤销、审计日志包含秘密。
- SMTP 故障、Worker 重启和重复领取不会丢任务或重复创建站内通知。
