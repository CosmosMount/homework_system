# Agent 工作流

## 权威来源优先级

发生冲突时按以下顺序处理：

1. 用户在当前任务中的明确要求。
2. 根目录 `AGENTS.md` 的项目工作规则。
3. `01-product-requirements.md` 的产品行为与非功能要求。
4. 专题文档中的页面、接口、数据、安全、上传和部署规范。
5. `15-decisions.md` 中已接受的架构决策。
6. `.agents/tasks/current-task.md` 的当前范围。

发现高层文档冲突时停止实现并先修正文档，不能选择对编码最方便的一版。

## 标准流程

```mermaid
flowchart LR
    A[读取记忆和当前任务] --> B[读取相关权威文档]
    B --> C[检查现有代码和迁移]
    C --> D[分析根因与影响]
    D --> E[创建唯一中文计划]
    E --> F[最小范围实现]
    F --> G[测试与安全复查]
    G --> H[更新文档和任务]
    H --> I[提交结果说明]
```

## 1. 接手任务

- 阅读 `.agents/memories/project_baseline.md` 和 `.agents/tasks/current-task.md`。
- 阅读总览、需求以及与任务相关的专题文档。
- 使用代码搜索确认实际模块、接口、迁移、测试和未提交修改；不能仅按聊天或文件名猜测。
- 识别对应需求编号、成功标准、明确不在范围内的内容和可能影响的数据。
- 若现有实现已能通过扩展满足需求，优先复用，不创建平行模块。

## 2. 建立计划

非简单任务在 `.agents/plans/` 创建一个 `plan_<object_name>.md`，使用中文说明：

- 问题背景与本质原因。
- 现有结构和可复用能力。
- 必要修改、涉及模块和不修改的后果。
- API、数据库、权限、迁移和部署影响。
- 测试与验收方式。

同一任务只有一个正式计划；调整直接更新原计划，不创建 `v2`、`final` 或备份副本。

## 3. 实现

- 先实现最底层约束和测试，再实现 Service、API 和页面，避免前端先发明行为。
- 数据库变化必须附 Alembic 迁移；API 变化必须同步 schema 和契约测试。
- 认证、权限、截止、幂等和对象引用在后端强制执行，前端只提供体验反馈。
- 写操作将业务数据、审计和 Outbox 放在同一事务。
- 分片文件不经过 API/Next.js 进程整体中转。
- 保留用户已有未提交修改，避免改动无关文件和大范围格式化。

## 4. 验证

按风险从小到大执行：

1. 格式、lint 和静态类型。
2. 受影响模块单元测试。
3. PostgreSQL/MinIO 集成测试和迁移测试。
4. API 契约与权限矩阵测试。
5. 关键浏览器流程和响应式/无障碍检查。
6. 涉及上传、Worker、部署或性能时执行对应专项验证。

测试失败先确认失败是否由本次修改导致；不得删除或放宽有效测试来获得通过。

## 5. 文档与任务收尾

- 更新受影响的产品需求、页面、API、数据库、安全、测试和部署文档。
- 跨模块或不可逆取舍新增/更新 ADR；用户可见或运维重要变化写入 `16-changelog.md`。
- 更新 `.agents/tasks/current-task.md`，完成项移入 `completed.md`，后续工作进入 `backlog.md`。
- 在形成稳定阶段性结论时更新 `project_baseline.md`，不把短期调试细节写入长期记忆。
- 最终说明修改内容、必要性、测试结果、迁移/部署影响和剩余风险。

## 变更类型检查表

### 认证或权限

- 覆盖允许与拒绝用例、账号状态、Session 撤销、CSRF、审计和枚举风险。
- 公开注册和管理员邮箱修改只能接受并验证 `@connect.hkust-gz.edu.cn` 邮箱；不得增加绕过邮箱验证的路径。
- 空系统首次管理员只能在成功消费验证令牌的事务内授予，并以 PostgreSQL 事务锁保证并发唯一；保持 `student`/`admin` 两角色、授予审计和最后管理员保护，CLI 创建管理员仅用于受控恢复。

### 通知与邮件

- 验证受众、幂等、站内提醒、Outbox、重试、失败可见性和内容脱敏。
- SMTP 失败不能回滚已提交的业务结果。

### 作业与赛事

- 验证受众/阶段、有效截止、所有者、队长、不可变版本和私密评语。
- 禁止加入评分、排名或公开反馈字段。

### 文件

- 验证大小、扩展名、内容类型、哈希、上下文、绑定、下载权限和孤立清理。
- 对象键永远由服务端生成，数据库不保存二进制。

### 数据库

- 更新 ER/字段文档，提供迁移、约束、索引和生产前备份策略。
- 在真实 PostgreSQL 上验证从空库和上个发布版本升级。

### 前端视觉

- 遵守 `03-design-system.md`，检查深色对比、键盘、焦点、移动端和全部数据状态。
- 不因视觉改动改变权限或绕过服务端状态。

## 紧急修复

安全或生产故障允许先建立最小修复计划并快速实施，但仍必须：

- 保留数据和用户现有修改，不使用破坏性回退。
- 添加能证明问题的回归测试或可重复诊断步骤。
- 在同一修复任务中补齐受影响文档、审计和变更记录。
- 若临时关闭功能，使用明确配置和恢复条件，不保留无期限旁路。

## 禁止事项

- 未读需求和当前任务就开始编码。
- 在 Router 写 SQL、在 Repository 判断业务角色、在前端代替后端授权。
- 为大文件改成 API 整体上传，或把附件写入 PostgreSQL。
- 使用公开对象桶、明文密码、长期 JWT、未清洗 Markdown 或真实学生数据测试。
- 随意改变技术栈、状态枚举、需求编号和已接受 ADR。
- 为展示或备份在 `.agents/` 外创建重复分析文档。
