# 阶段 6 容量与性能验收报告

## 结论

- 在隔离项目 pnx-stage6-performance、生产同等资源上限、300 个虚构学生容量数据下，100 个独立登录会话完成 2,000 次典型读取请求，错误率 0%，总体 P95 为 341.754 ms，满足“非上传 API P95 < 500 ms、错误率 < 1%”。
- 20 路并发 multipart 分别通过 1 MiB 协议样本和 100 MiB 容量样本；100 MiB 场景共上传 2,000 MiB、140 个分片，错误率 0%。
- 2,130,706,432 字节近 2 GiB 单文件以 1 MiB 生成块、127 个分片完成，未把大文件写入仓库或整体载入内存。
- 实测后将 Backend 收敛为 4 个 Uvicorn Web Worker、每进程数据库连接池 8+4，并把生产 Backend CPU 上限从 2 核调整为 4 核。数据库迁移和业务 API 均未改变。

## 验收范围与隔离边界

- 日期：2026-08-25（Asia/Shanghai）。
- Compose 项目：pnx-stage6-performance；入口：http://127.0.0.1:58082。
- 数据卷、端口和虚构账号均与 pnx-training 隔离；未向局域网开发数据注入容量或故障数据。
- 密码只从权限 0600 的绝对路径文件读取；工具不输出账号、密码、Cookie、响应正文、上传 ID 或文件 ID。
- 对象内容由确定性可打印模式按 1 MiB 块流式生成；分片 SHA-256 使用 Base64，请求完成校验使用完整十六进制 SHA-256。

## 2026-08-28：100 账号同出口同时登录补充诊断

本轮使用独立 Compose 项目 `pnx-loginburst-20260828a`、回环入口 `127.0.0.1:58082`、空 PostgreSQL `20260828_0013` 和相同的 300 个虚构学生容量数据。开发 Compose 未施加阶段 6 的生产 CPU/内存硬限制，因此本节只回答登录突发的正确性、入口行为和量级，不替代生产资源边界验收。

| 路径 | 成功 | 错误 | 总耗时 | P50 | P95 | P99 | 最大 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 同出口经 Nginx | 21 | 79 个 HTTP 503 | 1.641 s | 117.138 ms | 1,597.073 ms | 1,623.939 ms | 1,634.025 ms |
| 同网络直连 Backend 对照 | 100 | 0 | 5.293 s | 4,484.211 ms | 5,235.432 ms | 5,265.649 ms | 5,268.348 ms |

- Nginx 场景的 100 个请求由事件栅栏同时释放，起跑偏差 P95 21.847 ms、最大 23.051 ms。79 个错误均在 Nginx 日志中记录为 `limiting requests`，`upstream_time` 为空；配置为按 `$binary_remote_addr` 共享 `5r/s` 与 `burst=20 nodelay`，因此同一校园 NAT 出口只能立即放行约 21 个请求。
- Nginx 场景 Backend 峰值为 571.87% CPU、487.4 MiB、51 PID；PostgreSQL 为 13.32% CPU、102.7 MiB、28 PID；Nginx 为 2.13% CPU、15.11 MiB、17 PID。Backend 未重启且持续 healthy。
- 直连对照使用第 101～200 个虚构账号，起跑偏差 P95 111.457 ms、最大 126.990 ms，100 个请求全部成功。数据库最终核对该区间为 100 个 Session、100 个独立用户；连同入口首轮共有 121 个 Session/121 个用户，失败请求没有半 Session。
- 结果表明当前应用与数据库可以完整处理 100 个有效登录，但 Argon2 校验使同批登录等待达到约 4.5～5.3 秒；当前主要正确性阻塞是 Nginx 粗限流，而不是数据库连接池或 FastAPI 5xx。
- 安全修复不能简单移除限流：应把登录与注册/重置的粗粒度桶拆开，允许容量基线所需的短时正常突发，限制持续洪泛，继续由应用层按规范化账号与 IP 网段限制失败登录，并让 Nginx 拒绝返回 429。完成前不能宣称支持同出口 100 账号同时登录。
- 测试结束后已删除隔离容器、网络、PostgreSQL/MinIO 卷、专用镜像及 0600 临时密码目录；隔离压测步骤未影响 `pnx-training`，其后的独立功能部署不属于本压力场景。

## 限制与现场复验

- 本报告使用同宿主机回环 HTTP，验证应用、Nginx、PostgreSQL 和 MinIO 的服务端容量，不包含校园网络往返或生产 TLS 加密开销。
- 受信生产域名/证书、校园 SMTP、异机备份目标和独立告警接收方仍由部署方提供；材料到位后应在目标主机按相同命令重新建立现场基线。
- 近 2 GiB 验收为一个上限样本；20 并发能力由 100 MiB 场景独立验证，避免测试本身额外长期占用约 40 GiB。
