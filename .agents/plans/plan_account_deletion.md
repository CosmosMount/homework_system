# 管理员删除账号与用户自助注销计划

## 状态

已完成源码、加密完整备份、隔离恢复/迁移往返与生产部署（2026-08-29）。运行库已升级到 `20260829_0015 (head)`，应用固定标签为 `account-deletion-20260829`；部署与验收没有调用任何真实账号删除接口。

## 背景与必要性

现有 `DELETE /admin/users/{id}` 只允许永久删除严格超过 10 天未进入且没有正式业务引用的激活账号；存在提交、问卷、赛事、反馈答疑或文件等数据时会拒绝，用户本人也没有注销入口。当前目标是允许真实管理员删除指定账号，并允许有效用户注销本人账号，同时直接清除该账号的个人数据。

账号删除跨越认证、作业提交、问卷、赛事队伍、反馈答疑、文件和 MinIO，不能直接把所有用户外键改为无差别级联：删除创建过共享内容的管理员时，不能连带删除其他学生依赖的通知、作业、赛事、问卷或知识库快照。因此必须区分“目标账号的个人数据”和“仍属于平台/团队的共享业务记录”。

## 产品与安全口径

- 管理员可以删除任意非当前操作者账号，不再以 10 天不活跃作为删除前置条件；10 天活跃度继续只用于概览提醒和筛选。
- 用户可以在个人资料页注销本人账号。管理员若要删除本人账号也必须走用户自助注销路径，不能绕过当前操作者保护。
- 管理员删除请求必须同时提供至少 3 个字符的内部原因、管理员当前密码、规范化后与目标账号完全一致的邮箱确认，以及“已确认近期 PostgreSQL 与 MinIO 备份可恢复”的显式确认。
- 用户自助注销必须提供当前密码和规范化后与本人完全一致的邮箱确认。两条路径都必须通过有效 Session、同源、CSRF 和服务端重新认证；密码与邮箱确认不得进入日志、审计或错误正文。
- 禁止删除系统中最后一名激活管理员；使用既有管理员生命周期 advisory lock，并在删除前锁定一次性令牌、全部 Session、目标用户、队伍/文件等受影响记录重新复核。
- 成功和业务拒绝均写脱敏审计。成功审计只记录目标 UUID、调用模式、原角色/状态、管理员原因（自助注销使用固定原因）和各类删除计数，不记录邮箱、学号、姓名、密码、文件名、对象键、问卷答案、提交正文或工单正文。
- API 成功后账号行、Session、令牌和个人业务数据已经在同一 PostgreSQL 事务中删除。MinIO 无跨系统事务能力，因此对象键在同一事务进入可靠 Outbox；数据库引用立即消失，Worker 幂等终止 multipart 并删除对象。备份保留期内仍可能存在历史副本，页面和文档必须明确披露。

## 数据删除与共享留存边界

### 立即物理删除

- `users` 目标行、全部 Session、一次性令牌、站内通知和幂等记录。
- 作业正式受众成员、目标用户的个人延期、个人作业提交聚合及其版本、评语、优秀标记和个人附件关联。
- 目标用户的问卷回答及选项、反馈答疑工单、赛事报名和全部队伍成员记录。
- 目标用户未绑定的上传与对象，以及绑定到其个人作业提交的对象；数据库文件元数据在事务中删除，对象进入可靠清理任务。
- 与目标邮箱相关的认证安全事件去标识化；个人邮件 Outbox 去除收件人和姓名，活动任务取消并清除加密秘密。

### 保留并去除账号归属

- 通知、作业、赛事、问卷和知识库同步运行属于平台共享记录，创建者/更新者/触发者删除后字段置空，不删除根业务记录。
- 管理员为其他用户设置的延期、评语、优秀标记、取消资格、人数豁免和反馈答复继续保留，操作者字段置空；相关状态检查以时间、原因和正文作为业务事实，不再要求已删除操作者 UUID 永久存在。
- 团队赛事提交属于队伍。目标用户作为提交者时只去除提交者归属，不删除团队版本；其上传并已绑定到通知或团队版本的文件继续作为共享资源保留，`owner_user_id` 置空。
- 目标用户是队长时，优先把队长转给最早加入的当前其他成员；没有其他当前成员时把队伍置为 `dissolved`。删除后若锁定队伍低于最小人数且没有豁免，则转为 `invalid`。
- 审计日志继续只追加；目标用户作为操作者的历史记录由既有 `ON DELETE SET NULL` 去标识化，`target_id` 继续用于证明删除发生。

6. 管理员用户页为所有非当前账号提供内联高风险确认，要求原因、当前密码、目标邮箱和备份确认；个人资料页为学生和管理员提供注销区，要求当前密码和本人邮箱，成功后回到登录页。

- 后端纯单元/契约测试：管理员与本人成功路径；错误密码、错误邮箱确认、缺少备份确认、当前操作者管理删除、最后管理员、学生调用管理接口、管理员学生视图、CSRF；近期/待验证/禁用目标允许删除；审计不含秘密。

- Worker 纯 mock：对象删除成功、multipart 不存在幂等、对象存储故障进入重试、载荷错误进入 dead，测试不连接真实 MinIO。
- 前端 Vitest：管理员四项确认、取消、成功移除、错误保留；个人注销学生/管理员均可见，错误密码保留表单，成功跳转登录；页面不持久化密码。
- 静态质量门：Ruff、格式检查、严格 Mypy、ESLint、严格 TypeScript、相关 Pytest/Vitest 与 Next.js 生产构建。不得运行会读取 `DATABASE_URL`、Docker 运行 PostgreSQL/MinIO、Alembic upgrade/check 或当前 5000 写接口的验证。

## 备份、部署与回滚

- 本次开发不运行 `infra/backup/backup.sh`，因为它会读取当前 PostgreSQL 与 MinIO；遵守用户“当前数据库不用于测试”的限制。仓库已有加密 PostgreSQL + MinIO 周完整/日累计增量工具和恢复校验链。
- 原生产部署前置条件要求有权限的部署方新建并验证加密完整备份，同时确认归档、SHA-256、`pg_restore --list`、对象清单和异机保留。本次归档与从空环境恢复已验证，但异机保留尚未满足：加密归档和临时 GPG 密钥环仍同在本机 `/tmp`；这是已记录的部署例外和待闭环风险，不得视为前置条件已全部满足，也不能由管理员页面的备份确认替代。
- 先部署并应用 `0015`，再启用新删除入口。尚未执行账号删除时可降级回 `0014`；执行过删除后，应用和结构优先前滚修复，若必须恢复账号及个人对象只能从删除前 PostgreSQL 与 MinIO 同点备份隔离恢复。
- 若 Worker 暂时不可用，数据库删除仍保持提交，随机对象键不可再授权访问；Outbox 恢复后继续清理。最终失败必须由运维告警处理，不得通过桶扫描猜测并删除对象。
