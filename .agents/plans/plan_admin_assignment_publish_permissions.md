# 管理员作业发布权限一致性修复计划

## 状态

已完成（2026-09-05）。

## 背景与问题

运行日志显示，部分管理员在管理端新建或发布作业时收到 `403 FORBIDDEN`。只读会话聚合确认失败来源对应的账号真实角色为 `admin`、状态为 `active`，但当前 Session 仍保留 `student_view=true`。这通常发生在管理员已打开作业编辑页后，又在同一 Session 的其他页面切换到学生视图；旧页面随后提交管理请求时会被后端管理依赖正确拒绝。

项目仍只有 `student` 与 `admin` 两个角色，初始管理员不形成第三种角色，所有真实管理员应具有相同管理能力。学生视图继续作为受后端约束的临时预览模式，不能通过放宽管理接口鉴权来修复。

## 目标与范围

- 管理端作业写操作收到 `403 FORBIDDEN` 时，使用现有受 CSRF 保护的 `DELETE /auth/student-view` 尝试恢复当前 Session 的管理员视图，再重试一次原操作。
- 只有真实角色仍为 `admin` 的 Session 能关闭学生视图；普通学生、已被降级账号或其他真实无权请求继续由后端拒绝。
- 覆盖作业保存、创建、发布、关闭、删除和延期操作，避免同一页面内出现权限行为差异。
- 不改变作业发布状态机、受众快照、审计、Outbox、角色模型或后端管理依赖。

## 影响需求

- `AUTH-011`：保持学生视图的后端管理接口拒绝边界；前端陈旧管理页面在真实管理员身份仍有效时可显式关闭学生视图后继续操作。
- `HW-001`、`HW-003`：所有真实管理员都可通过同一管理页面创建、保存和发布作业。
- `NFR-002`：权限最终仍由后端真实 Session、角色、CSRF 与管理依赖判断，前端重试不构成授权。

## 实现步骤

1. 先新增前端回归，复现作业发布前保存草稿收到 `FORBIDDEN` 的场景，并断言只执行一次学生视图关闭和一次原请求重试。
2. 在作业管理组件内增加职责单一的管理请求包装函数，限定为 `FORBIDDEN` 时恢复管理员视图并最多重试一次；其他错误原样返回。
3. 让作业保存、发布、关闭、删除和延期复用该包装函数，不修改公共 API Client 或其他业务模块。
4. 更新页面、测试、变更、当前任务、完成记录和阶段记忆。

## 验证方式

- 前端定向运行管理员权限与作业交互测试。
- 运行完整前端测试、ESLint、严格 TypeScript 和 Next.js 生产构建；若共享工作区既有独立队伍候选导致范围外失败，单独记录并保留定向结果。
- 运行 `git diff --check`，确认不触碰独立队伍候选文件。

## 数据与部署影响

- 无新依赖、API Schema、数据库字段或 Alembic 迁移。
- 修复会在必要时把当前管理员 Session 的 `student_view` 从 `true` 改为 `false`，该变更沿用现有审计与 CSRF 保护，可由管理员之后再次主动开启学生视图。
- 本轮不携带管理员 Cookie 调用运行环境写接口，不创建或发布真实作业。

## 完成结果

- 已在作业管理组件内统一接入视图恢复与单次重试，覆盖创建、保存、发布、关闭、删除和个人延期；后端鉴权及公共 API Client 未修改。
- 已新增恢复成功和真实无权 Session 恢复失败两条回归。管理员权限定向 16 项、完整前端 25 文件/137 项、ESLint、严格 TypeScript 和 Next.js 16.3.2 生产构建均通过。
- 无依赖、API Schema、数据库或迁移变化；未调用运行环境真实管理写接口，未构建镜像或部署。
