# 管理员移除作业与通知计划

## 状态

已完成源码实现、完整质量门、隔离候选验证与生产部署；不涉及数据库迁移。

## 背景

管理员当前只能归档已发布通知或已发布/已关闭作业：通知归档后仍可由学生通过历史详情链接读取，作业归档后仍会出现在学生“全部/已截止”列表并可进入详情。草稿和定时内容也没有删除入口，因此管理员无法稳定地把误建或不再投放的内容从学生页面移除。

本任务对应通知域 `NEWS-003`、新增 `NEWS-009`，作业域 `HW-003`、新增 `HW-008`，并继续服从 `SUB-002～SUB-003`、`SHOW-003`、`FILE-003`、`NFR-002`、`NFR-006` 的不可变提交、附件存储、后端授权和审计约束。

## 目标与必要性

- 在通知、作业管理编辑页提供明确的“删除通知 / 删除作业”危险操作，并要求二次确认。
- 未发布内容没有学生历史：通知 `draft/scheduled` 和作业 `draft` 可以在同一事务内物理删除，同时取消仍活动的定时发布任务；通知附件只解除业务绑定，文件按既有孤立对象策略延迟清理。
- 已发布内容可能已有站内提醒、邮件、受众快照、提交版本、评语、优秀标记或附件引用：删除操作不破坏这些历史，而是受审计地转为 `archived`，并立即从学生列表、详情和作业内优秀作业入口隐藏。
- 已归档资源重复删除保持幂等；真实管理员和 CSRF 仍由现有管理依赖验证，管理员学生视图不得调用。

## 方案与影响

### 产品与决策

- 新增 ADR-040，明确“未发布物理删除、已发布归档删除”的统一语义，不新增全局软删除列或第二套状态机。
- `DELETE /admin/announcements/{id}`：草稿/定时通知物理删除；已发布通知归档并把未读公告提醒标为已读；已归档通知直接成功。
- `DELETE /admin/assignments/{id}`：草稿物理删除；已发布/已关闭作业归档；已归档作业直接成功。
- 删除接口统一返回 `204 No Content`。物理删除和归档删除都写动作、原状态与删除模式的脱敏审计。

### 后端

- Router 只增加两个 DELETE 协议入口；Service 负责状态分支、行锁、审计、事务和归档；Repository 负责实体删除与活动定时 Outbox 清理。
- 通知学生详情只允许 `published`；作业学生列表/详情排除 `archived`；优秀作业学生读取同时排除归档作业，真实管理员仍可查看留存记录。
- 不删除 `student_notifications`、已发送邮件 Outbox、提交版本、评语、优秀标记、文件元数据或 MinIO 对象；草稿通知解除附件关联后由既有孤立文件 Worker 清理。

### 前端

- 复用现有 Client Component、`csrfFetch`、`window.confirm` 和 `useRouter.replace`。
- 删除成功后返回对应管理列表；失败保留页面并展示统一 API 错误。
- 已发布内容的确认文案明确“学生端立即隐藏、历史记录保留”，未发布内容明确“永久删除未发布内容”。
- 保留旧归档 API 作为兼容路径，但编辑页不并列展示两个效果重叠的危险操作。

### 数据库与迁移

- 复用既有 `archived` 状态、外键级联和孤立文件清理，不新增字段、枚举、索引或 Alembic 迁移。
- `submissions.assignment_id` 的 `RESTRICT` 与正式版本不可变约束保持不变；已进入学生生命周期的作业不物理删除。

## 验证方式

- 后端服务测试：通知/作业草稿物理删除、活动发布任务取消、审计与提交；已发布内容归档删除；已归档幂等。
- 后端读取测试：归档通知详情 404；归档作业不进入学生列表/详情/优秀作业，真实管理员读取不受影响。
- OpenAPI 契约：两个管理资源路径包含 `DELETE` 且响应为 204；匿名、学生和学生视图继续由管理依赖拒绝。
- 前端组件测试：危险操作确认、DELETE 请求、成功返回管理列表、取消时不请求。
- 定向运行通知/作业/API 契约后端测试和管理员/通知前端测试；再运行 Ruff、格式检查、严格 Mypy、完整 Pytest、ESLint、严格 TypeScript、完整 Vitest，并在条件允许时运行 Next.js 生产构建。

## 风险与回滚

- 未发布内容物理删除不可由应用恢复；界面二次确认，生产操作仍依赖备份。附件对象不会随请求同步删除，可在孤立保留窗口内由备份或运维恢复。
- 已发布内容只做可追溯归档，不破坏学生正式提交；本轮不提供取消归档，误操作需通过受控数据恢复或后续明确需求处理。
- 应用回滚无需数据库降级；回滚后已归档资源可能按旧逻辑重新出现在作业学生列表或通过通知历史详情访问，因此若已使用删除操作，不应只回滚前后端而不同时保持本轮学生查询过滤。
