# 管理员权限与人员视图补齐计划

## 状态

已完成（2026-08-25）。

## 背景与问题

当前作业管理后端和管理员新建作业页面已经存在，但管理员个人资料页只有只读展示，且系统没有管理员查看全体登录会话的 API 与页面。用户无法完成管理员应有的个人资料维护和登录人员查看，容易误判为角色权限失效。

## 目标与范围

- 保持只有 `student` 与 `admin` 两个角色，所有新增接口继续由后端管理员依赖鉴权。
- 新增管理员查看全体未撤销登录会话的脱敏视图，包含用户基本身份、设备摘要、IP 网段和活动时间，不返回 Session 令牌或密码。
- 管理员个人资料页支持修改姓名、学号、校园邮箱，并复用现有管理员用户更新接口、revision、审计和邮箱变更重新验证规则。
- 核对并修复作业新建入口的管理员访问路径，不改变作业业务规则或数据库结构。

## 影响与验证

- 影响 Backend auth/users router/service/repository、Frontend 管理员导航、资料页和人员页，以及对应测试和 API 文档。
- 不涉及数据库迁移；不改变学生作业提交权限和管理员后端授权边界。
- 运行后端定向/完整测试、前端组件/页面测试、类型与格式检查，重建必要容器并验证局域网 `5000`。

## 安全约束

- 仅 `admin` 可访问全体登录会话；仅返回活跃会话，或明确标记已撤销会话但不返回敏感凭据。
- 会话列表按最近活动排序，邮箱和姓名属于管理员已有用户管理权限范围；日志和响应不包含 Cookie、token、密码或密文。
- 个人资料更新继续写审计；修改邮箱会撤销当前 Session 并要求重新验证。

## 完成结果

- 新增 `GET /api/v1/auth/admin/sessions` 与 `/admin/sessions`，后端使用管理员依赖鉴权，只返回未撤销、未过期且用户仍为 `active` 的脱敏会话信息。
- 管理员个人资料页已接入现有 `PATCH /api/v1/admin/users/{id}`，继续使用 revision、审计和邮箱修改后重新验证规则；学生资料页保持只读。
- 既有 `/admin/assignments/new` 页面、作业管理导航和后端管理员鉴权保持有效，并新增针对管理员访问入口的前端回归。
- 完整验证通过：后端 128 项测试、Ruff、135 个 Python 文件格式检查、100 个应用源文件严格 Mypy；前端 36 项测试、ESLint 和严格 TypeScript。
- `5000` 端口的 Backend live/ready、Worker 心跳和 MinIO 存活均为 200；新建作业、个人资料和登录人员页面匿名访问均重定向登录，管理员会话 API 匿名访问返回 401 而不是 404。
- 本次不涉及数据库结构变化或数据迁移。
