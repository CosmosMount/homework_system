# 管理员学生视图切换计划

## 背景

管理员需要在不改变真实角色的前提下查看学生工作台、通知、作业、赛事和个人提交界面，并能在同一会话中切回管理员界面。另一个管理员通过角色管理将其真实角色降为 `student` 时，必须撤销管理员能力；该变化不是可由本人按钮恢复的临时视图。

## 必要性

- 当前前端只按真实 `admin/student` 角色选择导航，管理员无法验证学生侧实际体验。
- 仅在前端隐藏管理员入口不足以形成权限边界；后端需要识别“管理员临时学生视图”并限制管理接口。
- 临时查看与真实角色降级必须分离，避免管理员通过切换按钮恢复被其他管理员执行的降级。

## 方案与影响

- 在服务端 Session 增加可撤销的临时 `student_view` 标记（数据库迁移可回滚），由当前管理员通过受保护接口开启/关闭。
- `AuthenticatedContext` 暴露真实角色和有效视图角色；学生业务接口使用有效视图角色，管理员管理接口始终要求真实 `admin` 且非学生视图。
- 切换开启/关闭写审计并更新 Session 状态；角色被其他管理员改为 `student` 时撤销该用户全部 Session，临时标记随 Session 消失，角色调整仍不可逆于本人。
- 前端在共享侧边栏增加“学生视图/返回管理员”操作，学生视图不展示管理员入口；切换后刷新当前页面，返回时回到管理员工作台。
- 更新认证 API、数据库、页面、测试、产品/架构/变更文档和当前任务；不新增第三种角色。

## 验证方式

- 后端单元/集成：开启与关闭视图、过期/撤销 Session、学生 API 放行、管理员 API 拒绝、角色降级撤销 Session 和最后管理员保护。
- 前端回归：管理员显示切换入口，学生视图显示学生导航且不显示管理入口，可切回管理员。
- 运行 Ruff、格式、Mypy、完整后端测试；前端 Vitest、ESLint、严格 TypeScript、Next.js 构建。
- 按项目约定重建 Backend/Frontend，重启 Worker/Nginx，并检查健康端点。

## 回滚

- 回滚应用提交并执行对应 Alembic 降级即可移除 Session 临时字段；真实角色变更审计与数据保持不回滚。

## 实际验收结果

- 后端 134 项测试、Ruff、严格 Mypy 通过；前端 47 项测试、ESLint、严格 TypeScript、Next.js 生产构建通过。
- `20260826_0008` 已应用，数据库 `sessions.student_view` 为非空布尔列；Backend、Worker、Frontend、PostgreSQL、MinIO、Nginx 均健康。
- 5000 端口健康端点均返回 200，匿名管理会话 API 返回 401，匿名学生/管理员业务页面均由登录守卫返回 307。

## 追加修复：作业受众预览

### 问题

发布受众由 `active_students_for_audience()` 仅筛选真实 `student` 账号生成固定快照。唯一管理员发布时没有普通学生，`assignment_audience_users` 为空，管理员开启学生视图后按快照查询会看不到作业。

### 实现

- `AssignmentRepository` 保留普通学生固定快照查询，新增基于作业当前届次/方向配置的服务端实时受众条件。
- 仅 `AuthenticatedContext.is_student_view` 为真时传入管理员作为 `preview_user`；列表、详情、提交、上传、优秀作业和附件下载共用该条件。
- 不写入受众快照，不生成通知/邮件，不改变统计目标人数；普通学生和管理员真实视图权限不变。

### 验证

- 新增仓储 SQL 受众预览回归；后端完整测试、Ruff、格式和 Mypy 通过。
- 重建 Backend/Worker，执行迁移检查并重启全部常驻服务；使用数据库和 API 验收唯一管理员的已发布作业可见性。
