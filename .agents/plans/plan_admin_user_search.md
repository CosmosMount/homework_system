# 管理员用户全量搜索与分页修复计划

## 状态

已完成源码修复、隔离候选验收、生产部署及后续发布回退纠正（2026-08-30）；当前合并镜像同时保留队伍删除与管理员全量用户搜索。

## 背景与必要性

管理员用户页目前固定以 `page_size=100` 只读取第一页，再在浏览器内对已加载账号做本地搜索。系统账号超过 100 个后，后续账号既不会显示，也无法通过姓名、邮箱、学号、中文角色或中文状态搜索命中；页面显示的总数虽然来自后端，却没有进入后续页的入口。

该问题违反 AUTH-007 的管理员账号管理能力、页面通用分页约定以及“筛选写入 URL”的信息架构要求。修复必须复用现有受管理员鉴权的 `GET /admin/users` 分页查询，不能把全部用户一次性塞入浏览器，也不能绕过后端权限边界。

## 实现范围

- 管理员用户页从 URL 读取 `search`、`page` 与既有 `activity`，服务端请求当前页并把查询条件传给后端。
- 用户列表使用固定、受控页大小，提供上一页/下一页、当前页、总页数和准确的匹配总数；空搜索可逐页查看全部账号。页码限制在 1～10000，取得 `total` 后把越界页规范化到实际末页。
- 搜索提交为 GET 并保留适用的活跃度筛选，翻页保留搜索和筛选参数；清除搜索回到对应筛选第一页。
- 后端继续在 Repository 查询全部账号范围，补齐中文/英文角色与状态名称的服务端匹配，并把 `%`、`_` 等字符按普通文本处理。
- 用户资料、角色、禁用/恢复和永久删除操作继续只作用于当前页已授权账号；成功后按同一 URL 条件重新获取服务端结果，删除导致末页收缩时回到新的末页，避免筛选结果残留或 OFFSET 跳项。不改变既有高风险确认、审计或最后管理员保护。

## 安全与数据约束

- `GET /admin/users` 继续使用 `AdminContextDependency`，学生、管理员学生视图和未登录用户不得读取账号列表。
- 响应字段不新增个人信息；只使用管理员原本可读取的姓名、学号、学校邮箱、角色、状态、方向与活动摘要。
- 不新增数据库字段、索引或 Alembic 迁移；不连接、读取或修改当前 PostgreSQL/MinIO 进行测试。
- 验证只使用纯 Mock、静态 OpenAPI、组件测试和本地构建，不调用运行环境 API 或真实账号写操作。
