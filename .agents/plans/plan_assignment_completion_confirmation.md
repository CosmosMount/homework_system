# 作业提交完成确认与三栏总览实施计划

## 问题背景

当前管理员可以在作业详情中区分当前受众的“已提交 / 未提交”，并进入个人提交审阅版本、附件、私密评语和优秀标记，但系统没有记录“管理员已经确认该提交完成”的业务事实。仅凭是否存在评语或是否提交无法表达审阅完成，也会让管理员在人数较多时反复打开已经处理过的提交。

本任务对应并扩展 HW-005、SUB-003、SUB-006、NFR-002、NFR-005～NFR-006、NFR-009。实现范围是个人作业提交的管理员确认和作业详情内的管理总览，不引入评分、等级、排名、自动判定或公开评语。

## 需求本质与必要性

- “已完成”是管理员对某个提交当前最新正式版本的人工确认，不是学生自报状态，也不是作业整体状态。
- 确认必须绑定具体不可变版本；学生创建更新版本后，旧确认不能自动覆盖新内容，该提交应重新进入“已提交、待确认”。
- 管理员误操作需要可撤销；确认与撤销都必须由真实管理员通过后端鉴权、CSRF、行锁和审计执行。
- 作业详情的三栏只以当前权威受众为统计口径，已退出受众但保留历史提交的人员继续单独展示，不混入当前三栏。

## 现有结构与可复用能力

- 复用 `submissions.latest_version_id`、同提交复合外键、不可变 `submission_versions`、管理员上下文、CSRF、审计和统一错误结构。
- 复用 `GET /admin/assignments/{id}/submissions` 的“当前受众并集历史提交者”完整分页装载，不新增重复名单接口。
- 复用 `/admin/submissions/[submissionId]` 审阅页和局部状态更新模式；完成确认不发送邮件或站内提醒。
- 复用现有管理页蓝白工作台、边框卡片和响应式栅格；不新增前端组件库、图片或依赖。

## 数据库与迁移

新增单一 Alembic 迁移 `20260908_0023`，在 `submissions` 增加：

- `completed_version_id UUID NULL`：管理员最近确认完成的正式版本；使用 `(id, completed_version_id) -> submission_versions(submission_id, id)` 的可延迟复合外键，禁止跨提交确认。
- `completed_at TIMESTAMPTZ NULL`：最近确认时间。
- `completed_by UUID NULL`：最近确认管理员，账号删除时 `SET NULL`，不影响已形成的业务事实。
- 检查约束保证 `completed_version_id` 与 `completed_at` 同时为空或同时存在。

迁移不回填历史提交，既有记录默认未确认；降级按“外键/约束后列”的逆序删除，可恢复到 `0022`。账号擦除预处理同时清空 `latest_version_id` 与完成确认字段，避免新增版本外键阻塞个人提交树级联删除。

## 后端实现

1. Submission 模型和响应增加完成确认元数据；管理员名单项增加 `is_completed`，其定义固定为 `completed_version_id == latest_version_id` 且两者非空。
2. 作业统计保留既有 `submitted_count`（全部已提交人数），新增 `completed_count`；页面中的待确认人数由两者差值得到，避免破坏既有统计语义。
3. 新增真实管理员接口：
   - `POST /admin/submissions/{submission_id}/completion`：锁定提交，确认当前最新版本；重复确认同一最新版本幂等返回当前状态。
   - `DELETE /admin/submissions/{submission_id}/completion`：锁定提交并撤销最近确认；未确认时幂等成功。
4. 确认和撤销只写脱敏审计，记录提交 UUID、作业 UUID和版本号/版本 UUID，不记录正文、评语、学生身份或附件信息；不发送提醒或邮件。

## 前端实现

- 管理员提交审阅页顶部展示当前完成确认状态，并提供“确认完成”按钮；确认后显示确认版本和时间，同时提供“撤销完成确认”。如果学生后来提交新版本，明确显示旧版本曾确认、当前最新版本待重新确认。
- 作业详情把当前受众按互斥规则分为“已提交（待确认） / 已完成 / 未提交”三栏；桌面并列，手机和平板按可读宽度自然纵向排列。
- 历史提交者继续在三栏下方独立展示，且不提供个人延期；确认状态可只作为历史信息显示，不计入当前三栏统计。
- 作业统计区域增加已完成与待确认数量；管理作业列表卡片同时展示完成进度，避免只显示总提交数造成歧义。

## API、权限与安全影响

- 两个新增写接口都要求真实 `admin`、有效 Session、同源和 CSRF；管理员学生视图、普通学生和匿名请求均不得调用。
- 完成确认不改变学生提交资格、截止时间、受众、版本不可变性、评语、优秀标记、附件授权或作业状态。
- 前端隐藏和按钮禁用不作为授权机制；并发确认/撤销由提交行锁串行化。
- API 变更同步 `06-api-specification.md`；数据库变更同步 `07-database-schema.md` 并提供可回滚迁移。

## 测试与验收

### 后端

- 确认当前最新版本、重复确认幂等、撤销及重复撤销。
- 新版本创建后，旧 `completed_version_id` 保留审计线索但 `is_completed=false`，名单回到待确认；再次确认更新到最新版本。
- 非管理员、管理员学生视图、无效提交和跨提交版本边界被后端拒绝。
- 当前受众的总提交、已完成、未提交计数正确；历史提交者不进入当前统计。
- 账号擦除能清空完成外键并继续删除个人提交树。
- OpenAPI 包含两个完成确认接口及新增响应字段。
- 迁移单一 head、`0022 -> 0023 -> 0022 -> 0023` 可往返，模型无漂移。

### 前端

- 审阅页确认和撤销调用正确接口，成功后按钮、版本和时间状态立即更新。
- 新版本晚于已确认版本时显示当前待重新确认。
- 作业详情把当前受众互斥分入已提交、已完成、未提交三栏，历史提交者保持单独区域。
- 管理作业列表和统计显示完成进度；空栏、窄屏语义、键盘按钮与 `aria-live` 状态保持可用。

## 明确不实施

- 不增加评分、通过/不通过等级、排名、量规、自动完成判定或公开评语。
- 不允许学生自行确认完成，不允许管理员代交或修改正式版本。
- 不把评语存在、优秀标记或作业关闭等价为完成确认。
- 不删除已退出受众的历史提交，不把历史提交者混入当前三栏统计。
