# 作业编辑页源码默认收起计划

## 背景

管理员作业编辑页当前同时展开 Markdown 源文本和已保存的渲染结果，源码占据页面上半部分，导致管理员看到的内容布局与学生详情不一致。

## 必要性

- 已保存作业应优先展示与学生相同的服务端安全渲染结果。
- 保留源文编辑能力，但不让实现细节默认占据阅读区域。
- 新建作业没有已保存内容时仍需直接提供 Markdown 输入，避免阻断创建流程。

## 修改范围

- 调整 `AssignmentEditor`：有已保存 HTML 的作业默认只展示渲染结果，源码通过明确的展开按钮按需编辑。
- 新建作业或尚无已保存 HTML 的草稿默认展开源码输入。
- 不修改后端 API、权限、Markdown 清洗策略、数据库结构或用户详情页。
- 增加管理员页面回归测试，验证默认隐藏、按需展开和内容仍正确提交。

## 验证方式

- 前端 Vitest、ESLint、严格 TypeScript 和 Next.js 生产构建。
- 检查已保存作业初始 DOM 不包含源码文本框，渲染标题/列表仍可见；点击编辑按钮后恢复源码输入。
- 运行受影响服务的镜像重建、重启和健康检查，不删除数据库卷或业务数据。

## 风险与回滚

- 交互只改变前端呈现，回滚本次提交即可恢复原先上下同时显示的编辑器。
- 源 Markdown 仍由原字段保存，未引入客户端解析或新的持久化路径。
