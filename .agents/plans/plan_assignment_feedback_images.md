# 作业私密评语图片计划

## 背景与目标

当前管理员可以为个人作业的具体不可变版本创建或修订私密 Markdown 评语，但评语只能包含文本；学生若需要查看圈画、截图或示意图，只能依赖评语外的渠道。平台已经具备 MinIO 分片上传、服务端内容探测、统一文件授权和安全图片内联能力，适合在既有边界内补齐评语图片，而不把二进制内容写入 PostgreSQL，也不引入公开链接。

目标是在不改变个人作业、不可变版本和私密评语可见性规则的前提下，让真实管理员为具体版本的评语上传安全图片，并让该提交所有者与真实管理员在评语区域直接查看。评语更新邮件和站内提醒仍不包含评语正文或图片。

## 影响需求

- SUB-006：评语可关联有序图片；创建或修订时正文、图片关联、提醒、审计和邮件 Outbox 同事务提交。
- FILE-003～FILE-007：图片内容继续只存 MinIO，对象键由服务端生成；上传、绑定、内联展示和下载均复用服务端授权与类型检测。
- NFR-002、NFR-004、NFR-006、NFR-011～NFR-012：学生只能读取本人评语图片，管理员接口继续要求真实管理员与 CSRF；网页提供响应式、可访问的图片展示，不把对象键、秘密或评语内容写入日志和审计。

## 产品与安全边界

1. 只允许 PNG、JPEG、GIF、WebP；拒绝 SVG、HTML、可执行文件、扩展名/内容不匹配和仅客户端声明为图片的文件。
2. 每条评语最多 10 张图片，单张最多 10 MiB，合计最多 50 MiB；浏览器预检不替代后端绑定事务复核。原计划的 5 MiB/20 MiB 边界经用户确认由 ADR-073 放宽。
3. 上传目的新增 `submission_feedback`，上下文固定为具体个人作业版本 UUID；只有真实管理员可以初始化、恢复、完成或终止该上传。
4. 评语保存请求显式携带的 `file_ids` 是该 revision 的完整有序图片集合，显式空数组表示移除全部图片；为兼容旧客户端，修订时省略该字段则保留已有集合。既有关联可保留、移除或调整顺序；新增文件必须属于当前管理员、当前版本上下文、状态可用且未绑定其他正式资源。
5. 学生本人和真实管理员通过登录态 `GET /files/{file_id}/content` 获取 5 分钟 inline 签名并直接显示图片；无权请求统一 404。下载能力保留，页面不嵌入永久 MinIO 地址。
6. 评语正文仍为必填安全 Markdown；图片不进入 Markdown HTML，不接受远程图片 URL，不随邮件发送，也不因优秀作业标记而公开。

## 实现范围

1. 新增可回滚 Alembic 迁移：扩展 `files.purpose` 检查约束，并创建 `feedback_files(feedback_id,file_id,display_order)`；对文件和顺序建立唯一约束，外键按评语删除级联、文件删除限制处理。
2. 扩展 Submission 模型、Repository、Schema 和 Service：批量锁定文件、验证上传上下文与安全图片边界、原子替换关联，并在响应中返回安全图片元数据。
3. 扩展 Upload Service/Repository：支持评语图片上传上下文、绑定识别、孤立文件判断、账号擦除共享文件分类，以及学生本人/管理员的下载和内联授权。
4. 管理员提交审阅页复用 `MultipartUploader` 上传评语图片，展示待保存图片并支持移除；已有图片默认随修订保留。
5. 管理员与学生评语区域按顺序直接渲染响应式图片，提供替代文本、懒加载和下载入口；加载失败时保留明确提示/下载能力。
6. 同步产品需求、页面、架构、API、数据库、安全、上传、测试、决策、变更、当前任务、完成记录和项目基线。

## API 与数据库影响

- `UploadInitRequest.purpose` 增加 `submission_feedback`，`context_id` 为 `submission_versions.id`。
- `PUT /admin/submissions/{submission_id}/versions/{version_id}/feedback` 增加 `file_ids: UUID[]`，最多 10 个且不得重复。
- `FeedbackResponse` 增加有序 `images`，每项只返回内部文件 UUID、显示文件名、大小、服务端媒体类型与 SHA-256；页面自行构造登录态内容入口。
- `GET /files/{file_id}/content` 从“通知正文图片”扩展为“受保护内联图片”，仅通知正文图片或已绑定评语的安全图片可用。
- 迁移降级删除 `feedback_files` 并恢复旧 purpose 约束；降级会丢失评语图片关联，但保留 `files` 元数据和 MinIO 对象，随后按孤立对象策略清理。生产降级前必须先备份。

## 验证方式

### 后端

- 初始化只允许真实管理员和存在的个人作业版本；普通学生、管理员学生视图、错误版本和 legacy 团队版本统一拒绝。
- PNG/JPEG/GIF/WebP 的扩展名、检测类型、10 MiB 单张/10 张/50 MiB 合计边界、所有者、上下文、状态和未绑定规则全部覆盖；跨版本、跨管理员、重复 UUID、危险类型和并发 revision 冲突整体回滚。
- 创建、保留、重排、移除和新增图片与评语 revision、站内提醒、审计、唯一邮件 Outbox 同事务；邮件 payload 不含图片或正文。
- 学生本人/管理员可内联与下载，无关学生和优秀作业受众不能读取；孤立清理、账号擦除和存储对账把评语图片作为正式引用处理。
- 迁移执行 `0025 → 0026 → 0025 → 0026`，检查约束、外键、唯一约束、索引和 ORM 元数据一致。

### 前端

- 管理员可选择多张图片、逐个上传、移除待保存项并与正文一次保存；上传失败保留正文和已完成图片。
- 创建与修订成功后立即显示图片；已有图片在仅修改正文时不丢失。
- 学生和管理员页面直接显示响应式图片，保留下载按钮、替代文本、懒加载和加载失败状态；窄屏无横向溢出。
- 普通提交附件、通知图片、评语正文、完成确认和优秀作业隐私回归不受影响。

### 质量门

- 运行相关 Pytest、Ruff、格式与严格 Mypy。
- 运行相关 Vitest、ESLint、严格 TypeScript 与 Next.js 生产构建。
- 运行 Alembic 单 head、迁移往返/模型漂移检查和 `git diff --check`。

## 完成条件

- 管理员能为具体作业版本的私密评语上传并保存最多 10 张安全图片，学生本人和管理员在网页评语区域直接看到图片。
- 图片权限与评语权限一致，未登录或无关学生不能借文件 UUID、优秀标记或短时地址读取。
- 文件内容不进入 PostgreSQL，邮件/提醒/审计/日志不包含评语图片内容、对象键或永久地址。
- 自动测试与静态/构建质量门通过；文档、当前任务与完成记录同步；明确迁移与遗留风险。
