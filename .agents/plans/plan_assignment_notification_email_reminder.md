# 作业与通知统一邮件提醒计划

## 背景与目标

管理员目前只能在通知首次发布时勾选邮件，或在通知修改后单独发送更新提醒；作业没有对应的邮件提醒入口。需要把两类内容都收敛为管理员显式点击的统一“发送邮件提醒”动作，并让提醒内容以当前内容 revision 为准，重复点击同一 revision 不重复入队。

评语仍保持只有提交者本人和真实管理员可见，邮件不包含评语正文、图片或对象地址；前端和邮件文案不再反复强调“私密”。

## 影响范围

- 通知与作业管理页增加统一邮件提醒按钮。
- Backend 新增作业和通知的显式邮件提醒端点，复用当前受众快照、CSRF、真实管理员鉴权和 Outbox。
- Worker 邮件模板增加作业提醒，并将通知发布/更新邮件统一为同一提醒语义；旧通知邮件任务类型继续兼容投递。
- 更新 API、页面、邮件与测试文档；不新增数据库字段或迁移。

## 业务规则

1. 只有已发布/已关闭且未删除的作业或已发布通知可以发送提醒；草稿、定时发布、归档和删除内容拒绝。
2. 发送时由服务端读取当前有效受众，邮箱只能来自用户记录；浏览器不得提交邮箱地址。
3. 事件键包含资源 ID 与当前 revision；同一 revision 重复点击幂等，内容保存后 revision 变化即可再次提醒。
4. 邮件正文只含称呼、标题、摘要/作业提示和站内登录链接。通知正文继续使用入队时安全 Markdown 快照；作业不包含提交、评语或附件内容。
5. 发送提醒只创建邮件 Outbox，不额外创建站内提醒；通知原有发布时站内提醒保留，历史 send-update 路径转用统一邮件提醒逻辑。

## 验证方式

- 后端覆盖管理员鉴权、状态校验、受众解析、事件键幂等、revision 变化再次入队、通知/作业邮件模板和旧任务兼容。
- 前端覆盖两个按钮、发送成功/失败反馈、移除发布/更新邮件区分和评语文案。
- 运行相关 Pytest/Vitest、Ruff、格式、Mypy、ESLint、TypeScript、生产构建和 `git diff --check`。

## 回滚

无数据库迁移。回滚入口时需保留 Worker 对新增邮件类型的处理，或先等待这些任务处理完成；直接回退到不认识新任务类型的旧 Worker 会导致任务失败。
