# 作业修正截止时间计划

## 背景与范围

正常截止后禁止首次提交，但已提交且收到评语的学生需要修正窗口；新增 `review_deadline` 作为最终上限。学生还需看到当前版本是否已由管理员确认完成。涉及 HW-001、HW-003～HW-007、SUB-001～SUB-006、SUB-009～SUB-010、FILE-002、NFR-005～NFR-009。本次包含生产部署。

## 已确认规则

- 正常截止前沿用现有规则。个人延期内可首次提交，无需评语，但延期不得超过修正截止。
- 正常截止及个人延期后，本人该作业任一正式版本已有评语即可多次修正，不要求最新版本重新收到评语或评语已读。
- 到达修正截止即拒绝新版本；提前关闭、归档、删除、受众移除仍阻止提交。
- 旧作业默认修正截止等于正常截止；有更晚个人延期时回填该作业最晚延期，这也会给该作业其他已获评语学生开放同一修正窗口。

## 实现

1. 新增非空 TIMESTAMPTZ 字段和 `review_deadline >= deadline` 检查。可回滚迁移回填旧记录，不改版本、评语和延期。
2. 创建省略/null 默认正常截止；更新省略保留原值（原值与正常截止相同时随新正常截止调整），null 重置为正常截止。修改仍要求 revision、锁和审计；修正截止前移不得早于历史提交或既有个人延期。
3. 在现有策略中统一详情、SQL 列表、正式提交和上传初始化资格。保留正常截止自动关闭任务；修正资格实时判断，截止前成功提交的幂等重放仍成功。
4. 前端增加管理字段、三类时间显示和修正/只读提示；提交入口遵从后端资格。列表筛选排序同步识别可修正作业。
5. 学生列表和详情独立展示提交资格与当前版本完成状态；API 摘要由既有确认版本字段派生，不增加数据库列。
6. 同步需求、页面、API、数据库、测试、决策、变更及任务记录，保留工作区其他任务改动。

覆盖时间边界、未提交/无评语/历史评语、多次修正、延期上限、越权、关闭与受众、幂等、上传跨截止；验证创建/编辑默认语义和并发锁。隔离 PostgreSQL 验证迁移往返、回填和模型一致性，执行前后端相关测试、静态检查、生产构建与端到端业务流程。生产上线另行备份验证；降级移除新增约束及字段，应用回退恢复旧截止规则。
