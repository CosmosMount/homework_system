# 认证前台异常与恢复路径修复计划

## 背景与问题本质

用户在移动端认证流程中观察到三类异常：验证链接已使用后按钮被禁用且缺少直接登录恢复路径；认证流程可能跳转到通用 404；注册失败只显示“服务暂时无法处理请求”，无法区分稳定业务错误、入口限流、非 JSON 网关响应和真正的服务端异常。

本任务不是放宽认证权限或暴露账号状态，而是让前端严格消费既有认证错误契约，并保证每个终态都提供安全、可继续的路径。后端仍统一处理账号不存在、密码错误、待验证和禁用状态，不输出密码、令牌、Cookie 或账号存在性。

## 影响需求与范围

- AUTH-001～AUTH-005、AUTH-009：注册、邮箱验证、登录和密码恢复。
- 认证页面 `/login`、`/register`、`/verify-email` 及其共享表单。
- 浏览器 API Client 的错误解析、认证成功后的安全跳转和通用 404 恢复入口。
- 必要时补充后端异常日志或稳定错误映射，但不改变数据库结构、不新增依赖或 Alembic 迁移。
- 不修改正在并行实现的管理员通知/作业删除功能及其文件。

## 实施步骤

1. 通过现有测试和源码复现：非 JSON/空错误响应、后端 `UNEXPECTED_ERROR`、`TOKEN_ALREADY_USED`、认证成功跳转与 `next` 参数边界。
2. 核对截图时间附近的运行日志；若需要 Docker socket 临时权限，先取得用户明确授权，并在诊断/部署后撤销。
3. 增加失败测试，固定错误解析不得因响应体格式再次抛异常；认证表单应展示稳定业务消息、请求 ID 和可执行恢复动作。
4. 修复验证页终态：已使用令牌明确提示可能已激活，提供直接登录与重新发送；不重复提交已消费令牌。
5. 修复登录/注册后的安全跳转：只接受允许的站内路径，登录成功默认进入与真实角色匹配的已存在页面；无效目标回退到角色首页。
6. 若根因来自后端未捕获异常，按 Router/Service/Repository 职责修复并保留统一错误码与脱敏日志。
7. 运行认证定向前后端测试、API Client 测试、完整质量门和生产构建；同步页面、API、测试、ADR/变更记录及任务台账。
8. 部署前备份并核对用户/认证事件基线，发布后验证移动端相关路径、健康端点与日志，最后撤销临时 Docker 权限。

## 验证方式

- API Client：标准 JSON 错误、空响应、HTML 网关错误、无效 JSON 和网络异常均转为可预期的 `ApiError` 或稳定网络提示，保留 HTTP 状态、`Retry-After` 与请求 ID。
- 验证页：有效令牌成功激活；已使用/过期令牌不进入 404，显示登录和重发恢复动作；令牌不进入日志或第三方跳转。
- 登录：正确凭据创建 Session；无效凭据和 10 分钟限流维持现有安全语义；恶意或不存在的 `next` 不导致外部跳转或认证后 404。
- 注册：字段/唯一性/密码错误展示具体安全消息；真正 5xx 展示统一提示与请求 ID，不能误报为密码或邮箱错误。
- 数据安全：不读取、输出、重置或批量重哈希真实密码；不删除用户、一次性令牌、安全事件或 Session；无数据库迁移。

## 风险与回滚

- 错误提示过细可能造成账号枚举，因此登录、重发和重置继续使用统一对外语义，只对不敏感的注册字段错误做精确映射。
- 已使用令牌可能代表此前验证成功，也可能是管理员操作后的历史链接；页面只提示安全的两种恢复动作，不查询或显示账号状态。
- 应用回滚只需恢复前后端代码和固定镜像标签；数据库、用户、密码哈希与安全事件无需回滚。
