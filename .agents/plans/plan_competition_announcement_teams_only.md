# 赛事公告与组队简化计划

## 背景

当前赛事管理页要求管理员创建至少一个赛题后才能发布，学生详情也把赛题/交付项作为核心入口。实际使用场景只有一条校内赛公告、报名和组队，不需要赛题或团队作品提交。

## 决策

- 赛事发布不再要求存在赛题。
- 管理端隐藏赛题编辑、新建赛题和赛题统计入口；学生端隐藏空赛题列表，详情页聚焦公告、时间和组队。
- 保留既有 `competition_tasks` 数据表和兼容 API，不做破坏性迁移；历史赛题数据可由旧接口读取，但新流程不再创建或依赖赛题。
- 保留现有报名/提交时间字段与状态机以避免数据库迁移和历史状态破坏；本轮不开放团队作品提交入口。

## 修改范围

- 后端移除发布前“至少一个赛题”的业务校验。
- 前端赛事管理页移除赛题编辑器和创建表单，学生详情移除赛题/交付项列表。
- 补充发布无赛题、公告展示和组队入口回归测试。
- 同步产品需求、页面说明、API/架构说明、变更记录和当前任务。

## 验证方式

- 后端赛事定向测试、严格 Mypy、Ruff 与格式检查。
- 前端赛事测试、Vitest、ESLint、严格 TypeScript 和 Next.js 生产构建。
- 重建 Backend/Frontend 镜像，重启 Backend/Worker/Frontend/Nginx，并检查四个健康端点；不删除数据库或对象存储数据。

## 回滚

- 回滚本次提交即可恢复赛题管理 UI 与发布前置校验；数据库结构和历史数据未改动。
