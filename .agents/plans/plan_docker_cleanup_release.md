# 当前 Docker 环境整理、分批提交与发布计划

## 背景与必要性

当前工作树在 `0dd63ca` 之后同时保留了三组已经完成开发、且部分已部署到 `pnx-training` 的改动：问卷管理详情与草稿编辑、反馈答疑与登录态匿名公开答疑、学生分类提醒与共享页面徽标。源码、权威文档和运行记录尚未形成对应 Git 提交，当前分支又已领先远端 14 个提交；若直接重建或清理 Docker，运行镜像、可回滚源码与文档证据会继续错位。

Docker 环境此前已经做过一次 PNX 版本收敛，并明确保留运行服务、PostgreSQL/MinIO 数据卷、备份以及有限回滚镜像。本轮清理的本质不是全局 `system prune`，而是先建立可回滚发布点，再精确删除本项目已退出的一次性容器、无引用旧应用镜像和残留隔离资源，最后以当前提交重建并验证 `pnx-training`。

## 现有结构与可复用能力

- 复用 `infra/compose/compose.yml` 的六个常驻服务、一次性 `migrate` 服务、固定 `APP_IMAGE_TAG`、健康检查和仅 Nginx 暴露主机端口的拓扑。
- 复用现有前后端完整质量门、Alembic 单一 head/模型漂移检查、PostgreSQL 17 自定义格式备份和四个运行健康端点。
- 复用既有 Docker 清理边界：只处理名称、标签或 Compose project 明确属于 PNX 的资源；不删除运行卷、业务备份、全局构建缓存或其他项目资源。
- 保留未跟踪的 `infra/compose/Dockerfile.knowledge-hotfix.backend`，除非差异审计证明它已无用途并获得单独删除授权；本任务不把历史临时文件误提交为发布源码。

## 提交与整理范围

1. 审计全部已跟踪和未跟踪差异，检查文件权限、秘密、迁移链和共享文件中的跨功能修改。
2. 按可独立审查的逻辑主题分批提交：
   - 问卷管理详情、草稿编辑及对应测试/正式计划；
   - 反馈答疑、已解答问题公开、`0014` 迁移及对应测试/正式计划；
   - 学生分类提醒、公告归档已读、共享导航徽标及对应测试/正式计划；
   - 权威文档、运行记录和本次 Docker 发布收尾。
3. 共享 API 类型或页面文件若同时服务多个主题，使用精确分块暂存；每个提交点必须保持可导入、迁移 head 唯一，不能为了拆分制造中间失效状态。
4. 不修改产品角色、权限、API 契约或数据库设计；本轮只整理已完成实现、补齐发布记录和必要的运维计划。

## Docker 清理与发布

1. 取得临时 Docker socket 访问后，只读盘点全部容器、镜像、卷、网络、Compose project、运行镜像 ID、端口与磁盘占用；把 PNX 资源分为当前运行、明确回滚、一次性退出、隔离残留和未知五类。
2. 发布前确认六服务健康、Alembic `20260828_0014 (head)`、最近成功知识库快照和数据基线；生成 PostgreSQL 17 自定义格式备份并校验归档、权限、大小和 SHA-256。
3. 使用新的固定发布标签从已提交源码构建 Backend/Worker 与 Frontend；运行一次性迁移并确认无额外迁移或模型漂移，再按 Backend/Worker、Frontend/Nginx 顺序替换服务。
4. 清理仅限明确属于 PNX 且不再被运行/回滚引用的已退出迁移容器、旧应用标签、悬空 PNX 镜像和已确认的隔离项目资源；保留 PostgreSQL/MinIO 运行卷、当前镜像、一个明确回滚版本、备份和其他项目资源。
5. 完成后撤销本轮临时 Docker socket ACL，并复核 socket 回到基础 `root:docker`、`0660` 权限。

## 验证方式

- Git：`git diff --check`、提交边界审计、秘密/忽略候选检查、最终工作树仅保留明确不提交的现场文件或完全干净。
- Backend：Ruff 检查与格式、严格 Mypy、完整 Pytest、Alembic 单一 head 与模型漂移检查。
- Frontend：ESLint、严格 TypeScript、完整 Vitest、Next.js 生产构建。
- Compose：配置解析、固定镜像标签、六个常驻服务 healthy、仅 Nginx 映射 `5000`，四个健康端点和登录页为 200，受保护页面/API 匿名守卫保持 307/401。
- 数据：发布前后用户、问卷、反馈答疑、知识库成功快照等只读计数保持预期；不触发邮件、飞书同步、账号删除或上传。
- 清理：列出实际删除的容器/镜像/网络及可恢复性；确认数据卷、备份、当前/回滚镜像和其他项目资源仍在。

## 影响与风险

- 本轮源码包含既有 `20260828_0014`，运行库已经处于该 head，正常发布不新增迁移；若检查发现运行库落后，必须先备份并按 Alembic 前滚，不能直接恢复旧库。
- Docker 清理和服务替换会短暂影响当前 `5000` 入口；在每个替换阶段等待健康，失败时回到清理前固定镜像，不自动降级数据库。
- 当前分支领先远端的提交和本轮新提交只在本地形成发布点；除非用户另行明确要求，本任务不向远端 push、不创建外部 Release，也不假称已完成带受信域名/证书的生产现场发布。
