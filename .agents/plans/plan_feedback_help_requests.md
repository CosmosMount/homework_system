# 反馈答疑工单实施计划

## 背景与必要性

当前平台已经具备登录态学生工作台、站内通知和管理员业务工作台，但学生没有一个受保护、可追踪的入口提交系统使用反馈或培训问题，也无法在管理员处理后查看正式答复。依赖群聊或线下转达会丢失上下文，且不符合内部平台对权限、状态和审计的统一要求。

本任务新增私密的“反馈答疑”工单域，对应新增需求 `HELP-001～HELP-006`。学生可以选择“系统反馈”或“问题答疑”，提交标题和详情；管理员查看全部工单并填写处理结果或答复；学生只查看本人记录及管理员答复。功能不扩展为公开论坛、即时聊天、附件系统、评分或多轮消息。

## 产品边界与关键决策

- 学生端路由使用 `/help` 与 `/help/[requestId]`，管理员端使用 `/admin/help` 与 `/admin/help/[requestId]`；所有页面与 API 均要求登录。
- API 使用 `/api/v1/help-requests` 和 `/api/v1/admin/help-requests`，避免与现有作业版本私密评语 `feedback` 表和接口混淆。
- 工单类型固定为 `system_feedback`、`question`；状态固定为 `open`、`resolved`。学生创建后不能修改、删除或公开；管理员提交非空答复后原子进入 `resolved`，可以按 `revision` 修订答复。
- 学生列表和详情始终按 `created_by == current_user.id` 授权，越权与不存在统一返回 `404 RESOURCE_NOT_FOUND`；真实管理员可查看和处理全部工单，管理员学生视图按学生身份提交和读取本人记录。
- 标题和详情按长度、去空白规则验证；详情与答复使用现有服务端安全 Markdown 清洗路径，禁止原始 HTML 和危险协议。
- 管理员首次答复和后续修订在同一事务写入审计与站内通知，通知只包含安全标题和站内详情链接，不包含完整问题或答复正文，不发送邮件。
- 新增 PostgreSQL 表保存结构化工单和答复，不引入新依赖、对象存储、Worker 或第二套通知机制。

## 影响范围

### 权威文档

- 更新产品需求、信息架构、设计系统、页面规格、系统架构、API、数据库、安全、测试策略、决策、变更记录和项目基线。
- 在集中追溯矩阵、权限矩阵和验收矩阵中加入 `HELP-001～HELP-006` 与 `HELP-T01～HELP-T08`。

### 后端

- 新增 `backend/app/help_requests/` 模块，严格采用 Router → Service → Repository → PostgreSQL 分层。
- 新增模型、Pydantic schema、学生/管理员路由、授权、分页筛选、答复事务、审计和站内通知写入。
- 在应用入口与数据库模型入口注册新模块，不复用含义不同的作业 `feedback` 实体。

### 数据库与迁移

- 新增迁移 `20260828_0014`，在当前 `20260828_0013` 单一 head 后创建 `help_requests` 表、检查约束、外键和学生/管理员列表索引。
- `upgrade` 仅创建新表，不回填或修改现有数据；`downgrade` 删除新表，会丢失已产生的反馈答疑数据。生产降级前必须备份，部署回滚优先采用前滚修复。

### 前端

- 在共享学生与管理员导航加入“反馈答疑”。
- 新增学生列表/创建表单/详情和管理员列表/筛选/详情/答复表单，复用现有 `AppShell`、`AdminPageHeader`、表单控件、状态标签、统一 API Client 和安全 Markdown 组件。
- 覆盖加载、空、校验失败、提交中、成功、越权与服务端错误状态；移动端保持单列和不依赖悬停的操作。

## 验证方式

- 后端定向：学生创建两种工单、本人列表/详情、他人 404、普通管理员视图创建拒绝、管理员学生视图本人路径、管理员筛选/详情/答复/修订、空答复与 revision 冲突、通知与审计原子性。
- API/安全：匿名 401、学生调用管理接口 403、CSRF 继续由全局中间件保护、响应不泄露其他学生身份或内部字段、Markdown 危险内容被清洗。
- 数据库：空库升级到 `0014`、`0013 → 0014 → 0013 → 0014`、外键/检查/索引和 Alembic 单一 head；真实 PostgreSQL 可用时执行往返。
- 前端：学生创建并看到状态、管理员提交答复、学生详情显示答复、中文类型/状态、不显示数据库枚举、表单错误与重复提交保护、导航权限和移动端可用性。
- 质量门：Ruff、格式、严格 Mypy、Pytest、ESLint、严格 TypeScript、Vitest、Next.js 生产构建。

## 完成标准

- `HELP-001～HELP-006` 的页面、API、数据库、权限、通知、审计与测试追溯一致。
- 学生不能读取他人工单，管理员学生视图不能进入管理端，未登录不能访问任何反馈答疑页面/API。
- 管理员答复后学生可在本人详情查看并收到不含正文的站内提醒。
- 不新增公开内容、即时聊天、评分、附件或重复 Markdown/通知实现。
- 最终交付明确列出修改文件、测试结果、迁移/回滚影响、运行态是否部署及遗留风险。

## 2026-08-29 正式修订：问题答疑解答后公开

### 背景与规则

- 新增 `HELP-007`：有效登录用户可查看管理员已经解答的问题答疑，帮助相同问题的学生复用正式答复。
- 公开状态由现有数据派生，仅 `request_type=question AND status=resolved` 可进入公开答疑；待解答问题和全部系统反馈始终私密，不新增数据库字段或迁移。
- 公开列表与详情不得返回或查询提问者 UUID、姓名、学号、邮箱；匿名互联网访问仍由 Session 鉴权拒绝。
- 原本人列表和详情接口继续按 `created_by` 严格隔离，管理员接口和答复事务不改变；答复首次保存后自动公开，修订后公开详情即时展示最新安全 HTML。
- 不扩展评论、追问、附件、点赞、评分或论坛能力。

### 实施与验证

1. 更新需求、信息架构、页面、API、数据库说明、安全、测试、ADR、变更记录和项目基线。

## 2026-08-29 正式修订：管理员删除反馈答疑

### 背景与规则

- 新增 `HELP-008`：真实管理员可以删除系统反馈或问题答疑，使误提、重复或不再适合保留的内容同步退出学生本人记录与登录态公开答疑。
- 工单没有正式提交、附件或独立归档生命周期，因此复用行锁事务物理删除，不新增软删除字段、状态或 Alembic 迁移。
- 删除前把目标工单相关未读解决提醒标为已读；历史已读提醒继续保留，避免未读徽标指向不存在资源，同时不抹除已发生通知历史。
- 删除审计只记录工单 UUID、类型、原状态、revision 与 `physical` 模式，不记录标题、学生身份、问题正文或答复。学生、未登录用户和管理员学生视图不得调用。
- 管理员详情使用二次确认，明确不可恢复及本人/公开页面立即消失；成功返回管理列表，失败保留页面并显示统一错误。

2. Repository 新增实体删除；Service 锁定工单、失效未读提醒、写脱敏审计并提交；Router 增加真实管理员、CSRF 保护的 DELETE/204。
3. 在现有管理员答复 Client Component 增加危险操作，复用 `csrfFetch`、`window.confirm` 和 `router.replace`。
4. 增加 `HELP-T12～HELP-T13`：覆盖待处理/已解决和两种类型、提醒失效、审计脱敏、回滚、404、角色拒绝、OpenAPI 204，以及前端确认/取消/错误。
