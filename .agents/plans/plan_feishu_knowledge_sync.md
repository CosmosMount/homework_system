# 飞书知识库同步与培训文档阅读计划

## 背景

当前平台负责新生培训作业与校内赛动态流程，学生仍需要在培训期间查看飞书知识库中的培训文档。同步顺序、块转换和失败语义固定以现有 PNX 官网参考仓库提交 `c28f8a0` 为契约；知识库内容区的初版参考排布已由 ADR-033 定向替代为白色主题、左文档目录、中央正文和右本文目录。本平台继续保留登录态 `AppShell`、受保护 API、成功快照和 MinIO。

本任务不复制或依赖现有官网运行时，也不把飞书变成在线请求依赖。平台只通过飞书开放 API 生成只读快照，学生请求始终读取本地最后一次成功快照。

## 必要性与需求编号

- `KB-001`：登录用户可以查看最近一次成功同步的培训知识库目录与文档。
- `KB-002`：阅读器支持目录搜索、查询参数选中文档、飞书内部文档跳转、桌面/移动目录和本文标题导航。
- `KB-003`：结构化渲染段落、标题、列表、引用、代码、分隔线、提示块、表格、图片、白板和安全附件，不渲染飞书提供的任意 HTML。
- `KB-004`：管理员可以手动创建异步同步任务并查看最近同步状态；同一时刻最多一个同步运行。
- `KB-005`：同步失败不得替换最后一次成功快照；失败信息必须脱敏，前端与日志不得暴露飞书凭证、令牌或原始错误正文。
- `KB-006`：媒体文件存入 MinIO，PostgreSQL 只保存结构化块和媒体元数据；对象键由服务端生成。
- `KB-007`：知识库 API 必须登录鉴权，管理接口必须校验真实管理员角色及 CSRF；管理员学生视图只能访问学生读取接口。
- `KB-008`：外部链接仅允许安全协议；飞书 API 固定可信主机；附件按既有扩展名、媒体类型和大小策略校验，不安全附件只保留飞书原文回退。

## 约束与架构决策

- 新增 ADR，明确本功能取代 ADR-002 中“不复制培训知识库”的绝对限制：允许从飞书同步只读业务快照，但仍禁止修改或依赖现有官网运行时。
- API Router 只负责协议转换、依赖注入与状态码；Service 负责并发同步、快照切换、授权和安全规则；Repository 负责持久化。
- 管理员 `POST /api/v1/admin/knowledge/sync` 只创建同步运行与 Outbox 任务并返回 `202`；常规更新只有 Worker 访问飞书公网，首次上线内部命令可接管唯一活动运行并复用同一同步器。
- 成功快照由最新 `succeeded` 同步运行自然确定，不维护额外可漂移的“当前版本”单例记录。
- 飞书 `app_id`、`app_secret` 和知识库配置来自环境变量或 secret file；不得进入数据库、前端响应或日志。
- 使用结构化 JSON 块并依赖 React 默认文本转义；不信任或渲染任意 HTML。
- 不为推测性增量同步、定时任务、多知识库或公开分享新增抽象。

## 数据库与回滚

新增可回滚迁移 `20260827_0011`：

- `knowledge_sync_runs`：保存 `pending/running/succeeded/failed` 状态、来源、触发管理员、起止时间、文档/媒体计数与脱敏错误；部分唯一索引保证最多一个进行中运行。
- `knowledge_nodes`：保存某次同步的目录树、节点类型、父节点、深度和顺序。
- `knowledge_documents`：保存某次同步的文档标识、标题、来源 URL、结构化块 JSONB 和顺序。
- `knowledge_assets`：保存服务端对象键、受控文件名、媒体类型、大小、哈希和图片尺寸；按飞书资源标识复用。
- `knowledge_document_assets`：保存文档与媒体关系，用于只授权当前成功快照实际引用的资源。

降级时按关联依赖逆序删除上述表与索引，不删除 MinIO 中已经写入的对象；对象清理由应用后续安全回收处理，避免数据库回滚造成不可恢复文件丢失。

## API 影响

- `GET /api/v1/knowledge`：返回当前成功快照元数据、目录树和文档摘要。
- `GET /api/v1/knowledge/documents/{document_id}`：返回当前快照内的文档结构化块。
- `GET /api/v1/knowledge/assets/{asset_id}/content`：鉴权并确认当前快照引用后，跳转到短时 MinIO 签名 URL。
- `GET /api/v1/admin/knowledge`：返回当前快照与最近同步状态，不返回秘密。
- `POST /api/v1/admin/knowledge/sync`：真实管理员鉴权与 CSRF，创建异步同步；已有进行中任务时返回 `KNOWLEDGE_SYNC_IN_PROGRESS`。

## 安全与失败策略

- 所有读取接口要求有效登录 Session；管理接口使用真实角色，不能被管理员学生视图绕过。
- 对资源下载同时验证“最新成功快照—文档—资源”关系，不接受对象键或任意 URL 参数。
- 外链仅允许 `https`，飞书内部链接只映射已同步文档；未知或不安全链接显示为纯文本或受控回退。
- 同步错误只保存稳定错误码和脱敏说明；不记录 secret、tenant token、Cookie、对象键或飞书响应正文。
- 同步事务仅在整套目录、文档与引用关系就绪后标记成功；失败运行不会成为读取快照。

## 风险与边界

- 飞书开放 API 的块型和权限可能随租户配置变化；未知块型保留可读占位，不让整次同步因单个展示块失败。
- 大型知识库的首次同步可能耗时较长；任务由 Worker 异步执行并受页数、文档数、媒体数与单文件大小上限保护。
- 无有效飞书凭证时功能仍可部署，但管理员同步会得到明确的安全配置错误，学生看到“尚无成功快照”。
- 本任务不包含定时同步、多人共同编辑、公开访问、全文内容搜索、知识库写回或官网发布。

## 2026-08-27 首次上线前台初始化修订

### 背景与必要性

- 首次 227 节点全量同步在 Worker 内串行执行，首轮约 27 分钟后以 `KNOWLEDGE_SYNC_FAILED` 重试，第二轮运行约 20 分钟仍未完成；长任务同时阻塞 Worker 心跳和 Outbox 租约续期，无法满足首次上线速度。
- 用户要求先以前台运维命令完成一次初始成功快照，之后仍由现有管理员手动更新接口创建 Worker 任务；不得新增第二套业务写接口或绕过快照安全规则。

### 实施策略

1. 安全停止正在重试的 Worker，确认不存在并发同步进程；保留当前同步运行和 Outbox 记录用于可追溯接管。
2. 新增内部一次性前台初始化命令，复用 `KnowledgeSynchronizer`、现有配置、数据库和 MinIO 适配器，按最新 active run 接管；命令输出阶段与脱敏进度，不输出凭证、token、Space ID、对象键或飞书响应正文。
3. 前台命令始终复用参考契约同步器：目录和 Docx 串行，附件先处理，图片受 350 ms 共享队列约束，白板直接请求；继续保留文档/媒体总数、单文件大小、受信端点、内容校验和最终原子快照切换。
4. 前台命令成功后恢复 Worker；Worker 重领旧 Outbox 时识别已成功 run 并将任务收敛为 `sent`。现有 `POST /api/v1/admin/knowledge/sync` 及管理员页面继续保留，后续更新仍由 Worker 异步执行。

### 验证方式

- 单元测试覆盖参考同步顺序、前台命令只接管 active run、无 active run 安全失败、完整媒体同步、成功/失败退出码和秘密不输出。
- 完整后端 Pytest、Ruff、格式和严格 Mypy；开发/生产 Compose 解析。
- 运行态核对前台命令完成 `succeeded` 快照、学生知识库目录/文档/媒体可读、Worker 恢复 healthy、旧 Outbox 收敛，以及管理员接口仍返回 `202` 并创建后续 Worker 任务。

本修订不涉及数据库迁移，不改变公开 API 契约、角色授权或学生读取规则。

### 同步办法对齐

1. 同步开始显式获取 tenant token；空间目录按参考脚本使用 `page_size=50`、`page_token` 分页和串行 DFS 先序递归，任一目录错误整次失败。
2. Docx 按目录顺序逐篇串行处理；每篇先分页读取 blocks，再请求文档元数据标题。任一正文或标题错误整次失败，不跳过单篇正文。
3. 每篇文档内先发现独立附件和富文本内联附件，再转换块并处理图片、白板；Drive 图片/附件共用串行队列且请求前间隔 350 ms，白板按参考请求发送 `Accept: image/png`。
4. 图片或白板单项失败按参考实现跳过对应块，附件失败显示整篇“在飞书查看”回退；目录、正文和标题失败不得产生部分成功快照。
5. 前台初始化命令复用上述同一同步器并同步媒体；管理员 `POST /api/v1/admin/knowledge/sync` 保持不变，后续仍由 Worker 执行。
