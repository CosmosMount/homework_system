# 反馈答疑管理员提醒、附件页内预览与作业返回路径计划

## 背景

当前平台已经具备学生反馈答疑、管理员答复、学生侧解决提醒、受保护附件下载和个人作业版本详情，但存在三个实际使用断点：

1. 学生新建系统反馈或问题答疑后，管理员只能主动进入列表发现，管理侧导航没有未读提示。
2. 通知、个人作业和优秀作业的附件只能先下载，图片、PDF、当前白名单内的视频和纯文本等浏览器原生安全类型不能在当前网页直接查看。
3. 从作业详情进入个人版本或从管理作业进入某位学生提交后，详情页的上一级返回入口没有稳定回到原作业上下文。

## 必要性与需求影响

- 扩展 `HELP-001`、`HELP-003`、`HELP-005`：学生创建工单时，在同一事务为当前有效管理员创建不含正文和学生身份的幂等站内提醒；管理员侧“反馈答疑”入口显示蓝点，打开对应详情只标记本管理员的该条提醒已读，工单解决或删除后清除其余管理员的待处理提醒。
- 扩展 `NEWS-005`：`student_notifications` 继续作为唯一站内提醒表，但接收人可以是学生或管理员；学生四类计数保持不变，管理员只消费反馈答疑创建提醒。
- 扩展 `FILE-005`、`FILE-007`：下载授权不变，在同一业务反查授权之上增加短时页内预览地址；仅允许服务端检测为图片（不含 SVG）、PDF、浏览器安全音视频或纯文本的对象使用 `inline`，其他类型继续只下载。
- 明确 `SUB-003`、`HW-005` 与信息架构返回规则：学生个人提交详情返回 `/assignments/{assignment_id}`，管理提交详情返回 `/admin/assignments/{assignment_id}/edit`，不丢失作业上下文。
- 继续满足 `NFR-002`、`NFR-004`、`NFR-006`、`NFR-008`、`NFR-011`、`NFR-012`：所有提醒、预览和已读写入均由后端鉴权；提醒不含工单正文和身份；预览不放宽 HTML/SVG/可执行文件边界，不暴露对象键。

## 方案

### 1. 管理员反馈答疑蓝点

- 在反馈答疑创建 Service 事务内查询当前 `active admin`，为每人写一条唯一 `help_request_created:{request_id}` 站内提醒，目标指向 `/admin/help/{request_id}`。
- 复用 `student_notifications` 的 `(user_id, event_key)` 唯一约束，不新增通知表；名称作为历史兼容保留，在文档中明确它是登录用户站内提醒。
- 管理布局读取当前管理员的反馈答疑创建提醒未读数，并在“反馈答疑”导航显示蓝点而非正文或数量噪声。
- 管理详情响应只返回当前管理员、当前工单的未读创建提醒 ID；页面打开成功后复用受 CSRF 保护的单条已读接口，不让 GET 产生副作用。
- 工单首次解决时只把所有管理员的 `help_request_created` 未读提醒标记为已读，再创建学生解决提醒；删除继续让该工单全部未读提醒失效。

### 2. 受保护附件页内预览

- 在文件 Service 中集中定义浏览器可预览的检测媒体类型与安全扩展名双重允许列表，拒绝 HTML、SVG、脚本、可执行文件、Office、压缩包和未知二进制。
- 新增 `POST /files/{file_id}/preview-url`，完全复用下载接口的业务关联授权，返回 5 分钟同源 MinIO 预签名 GET，并强制安全 `Content-Type`、`Content-Disposition: inline`；不返回对象键。
- 扩展对象存储适配器支持预签名响应头覆盖；下载接口继续强制 `attachment`，避免语义混用。
- 在共享附件组件中保留“下载”，对可预览类型增加“预览”；图片、PDF、当前白名单内的视频和纯文本在当前页可关闭浮层展示，支持 Escape、焦点恢复、加载失败和重新获取过期地址。
- 通知附件、个人版本、管理员提交和优秀作业等所有复用共享附件组件的页面同步获得该能力；未复用处统一收敛到共享组件，不保留重复预览路径。

### 3. 来源感知返回路径

- 学生个人提交详情的返回入口与面包屑父级固定为当前作业详情。
- 管理员个人提交详情从响应中的 `assignment_id` 构造当前作业编辑/管理详情 `/admin/assignments/{assignment_id}/edit` 返回入口。
- 优秀作业详情继续保留当前作业内嵌路径；补充回归避免返回全局作业列表或错误角色页面。

## 数据、API 与安全影响

- 预计不新增数据库字段或 Alembic 迁移；复用 `student_notifications`、既有用户角色/状态索引与文件关联关系。
- 新增一个受保护文件预览 URL API，并扩展管理反馈答疑详情/未读聚合响应；先同步 `06-api-specification.md`。
- 预览 URL 与下载 URL 同为短时同源签名，只允许 GET；响应头覆盖由服务端根据已检测媒体类型生成，客户端不能指定任意媒体类型或 disposition。
- 工单提醒标题使用固定安全文案或工单安全标题，不含正文、答复、姓名、学号、邮箱；已读操作继续要求 Session、同源和 CSRF。

## 验证方式

### 后端

- 学生创建两类工单时，所有当前有效管理员各有且只有一条提醒；`student`、`pending_email`、`disabled` 不接收。
- 创建事务中提醒写入失败时工单和审计一起回滚；重复事件不生成重复提醒。
- 管理员只能读取/标记本人提醒；打开详情只清本人的当前工单提醒，首次解决清除其余管理员的创建提醒且不误清学生解决提醒；删除清除目标工单未读提醒。
- 预览与下载复用全部通知/个人版本/优秀作业授权矩阵；他人文件与猜测 UUID 返回 404。
- 图片、PDF、允许音视频和纯文本生成 `inline` 签名；HTML、SVG、Office、压缩包、EXE 和未知类型返回稳定不支持错误；下载仍为 `attachment`。

### 前端

- 管理侧“反馈答疑”在有未读创建提醒时显示蓝点，打开对应详情后消失；学生侧原四类徽标不回归。
- 共享附件在支持类型显示预览入口，浮层支持键盘关闭、焦点恢复、加载/失败状态；不支持类型只显示下载。
- 学生个人提交详情返回当前作业页；管理员提交详情返回当前管理作业页。
- 运行相关 Vitest、严格 TypeScript、ESLint 和 Next.js 生产构建。

### 综合

- 运行反馈答疑、通知、文件授权、提交/优秀作业相关后端定向测试，并按风险补充完整后端测试、Ruff、格式和严格 Mypy。
- 更新产品需求、信息架构、页面、系统架构、API、数据库、安全/邮件、文件存储、测试策略、ADR、变更记录、当前任务与完成记录。

## 迁移与回滚

- 本任务预计无数据迁移。应用回滚不需要 Alembic 降级；新版本产生的管理员提醒是既有表中的普通记录，旧应用会忽略其管理 URL，不影响学生提醒读取。
- 若实现过程中证明现有约束无法安全表达管理员提醒，必须先补充可回滚迁移并更新本计划、`07-database-schema.md` 与迁移测试，不能直接手工改库。
