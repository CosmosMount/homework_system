# 站内内容引用知识库文档计划

## 背景与必要性

公告正文、作业说明和作业私密评语都使用安全 Markdown，但管理员目前只能手工粘贴链接，无法从最近成功的站内知识库快照中选择文档，也无法保证重新同步后仍指向同一篇最新文档。用户所称“评论”按现有产品模型对应管理员针对个人作业版本的私密评语；本任务不新增评论区、追问或多轮讨论，继续遵守 HELP-006 和既有产品边界。

## 目标与范围

- 为公告正文、作业 Markdown 说明和私密评语编辑器提供统一的知识库文档选择器。
- 选择器只读取登录态 `GET /knowledge` 最近成功快照，支持按标题筛选；没有成功快照时显示明确空状态。
- 选择文档后在当前光标插入标准 Markdown 链接，链接使用稳定的知识库来源标识而不是本次快照 UUID；后续成功同步后仍解析到最新快照中的同一文档。
- `/knowledge` 同时兼容既有 `?doc=<当前快照文档 UUID>` 与新增 `?source=<稳定来源标识>`，无效参数回到知识库根层空状态，不泄露其他快照或上游内容。
- 公告邮件把站内知识库相对链接规范化为平台绝对地址；站内页面继续经过统一 Markdown 清洗，不允许任意协议、HTML 或外部脚本。

## 受影响需求

- NEWS-001、NEWS-006～NEWS-007：公告正文可插入站内知识库文档引用，邮件中的引用可访问。
- HW-001、HW-006～HW-007：作业说明可插入站内知识库文档引用。
- SUB-006：私密评语可插入站内知识库文档引用，评语权限、提醒与邮件隐私不变。
- KB-001～KB-002、KB-005、KB-007：引用只解析最近成功快照，阅读仍要求登录。
- NFR-002、NFR-004、NFR-011：后端授权不变，选择器可键盘操作，Markdown 继续安全清洗。

## 实现方案

1. 新增复用组件 `KnowledgeReferencePicker`，打开时通过登录态 API 读取知识库总览，在本地按标题过滤并返回所选文档的 Markdown 链接。
2. 新增纯函数处理 Markdown 链接标题转义、稳定引用 URL 和光标插入，三个编辑器共用，避免重复实现。
3. 公告、作业和评语文本框保存各自 `ref`；插入后恢复焦点并把光标移动到引用末尾。归档/只读内容不显示插入操作。
4. 知识库页面按 `doc` 优先、`source` 次之解析当前成功快照；前端阅读器更新 URL 时继续使用内部 UUID，不改变现有目录和浏览器历史行为。
5. 邮件渲染只把 `/knowledge?source=...` 形式的站内相对链接补全为配置的 `APP_BASE_URL`；其他相对/外部链接保持既有安全规则。

## 安全与数据边界

- 不新增数据库表、字段、Alembic 迁移、依赖或飞书写操作。
- 稳定来源标识只来自登录后已返回的当前成功快照，插入值进行 URL 编码；服务端阅读仍以当前成功运行和登录鉴权为边界。
- 引用不是内容复制，不把知识库正文写入公告、作业或评语，也不扩大原内容受众。公告受众、作业受众和私密评语权限继续独立执行。
- 私密评语邮件仍只提示“评语已更新”，不包含评语正文或知识库引用。

## 验证方式

- 前端单元测试覆盖空快照、标题搜索、三处插入、Markdown 特殊字符转义、光标位置、只读状态和 `source` 参数解析。
- 后端邮件测试覆盖站内知识库相对链接转为绝对链接、危险协议继续被清洗。
- 复跑知识库、公告、作业和评语定向测试，以及完整前端 Vitest、ESLint、严格 TypeScript、后端 Ruff 和相关 Pytest。
- 更新需求、页面、架构、API、安全、测试、决策、变更记录、当前任务与完成记录。

## 数据迁移与遗留风险

- 不涉及数据迁移。
- 既有手工粘贴的快照 UUID 链接不会自动改写；新选择器生成稳定引用。若飞书侧删除并新建文档导致来源标识变化，旧引用会安全回到知识库根层空状态，由管理员重新选择。
