# 新激活与新入组学生作业受众补录计划

## 2026-09-08 增量：新加入技术组后补录历史作业

### 背景与根因

管理员在用户页单独配置技术方向、或通过“意向选择”问卷批量配置方向时，只更新 `users.direction_id`，不会同步 `assignment_audience_users`。学生读取严格依赖该权威受众表，因此新加入技术组的同学看不到该组此前已经发布或关闭、但尚未归档删除的作业。

### 必要性与需求影响

- 调整 AUTH-007、HW-002、HW-006 与 INT-008：激活学生的技术方向实际变化为非空值时，在同一事务追加当前分类匹配的历史作业受众。
- 同时覆盖用户管理单人修改与问卷第一志愿批量配置，避免同一业务结果因入口不同而产生权限差异。
- 已发布和已关闭作业均可补录用于历史阅读；原截止时间、个人延期和提交资格继续生效，补录不等于允许逾期提交。
- 只追加缺失受众，不移除旧组作业，不补录草稿、归档或已删除作业，不补发历史提醒或邮件。
- 复用现有表、唯一键和 API，不新增表结构或接口字段；增加纯数据迁移 `20260908_0024`，为升级前已在技术组中的 active student 幂等回填缺失受众。

### 实施与验证

1. 作业 Repository 增加“按学生当前分类补录未归档历史作业”的单一职责方法，复用既有全体/方向及 legacy 届次的 union/intersection 匹配规则并跳过已有快照。
2. 用户管理 `PATCH /admin/users/{id}` 在 active student 的方向实际变化后调用补录，并与用户更新、审计原子提交。
3. 问卷第一志愿批量配置只为方向实际变化的 active student 调用同一补录能力；任一失败使整批方向、受众和审计回滚。
4. 增加 Repository、单人修改和批量配置回归，覆盖已发布/已关闭补入、草稿/归档/已删除/已有受众跳过、相同方向及清空方向不补录。
5. 增加可回滚纯数据迁移，为现有 active student 补录缺失受众；固定 `created_at` 标记使 downgrade 只删除本次迁移插入行。
6. 同步产品、页面、API、数据库、测试、ADR、变更与任务记录；运行后端定向测试、完整测试及 Ruff、格式、严格 Mypy。

### 回滚

- 应用代码可回滚且无数据库结构降级；若必须降级 `0024`，会删除迁移固定标记的回填行。
- 已追加的受众会保留，因为学生可能已据此阅读或形成正式提交；如业务确认误配，应通过现有管理员作业受众编辑按作业纠正，禁止直接删除提交或附件。

### 实际部署结果

- 候选以当前生产 Backend 镜像为基线，只覆盖 Repository、用户 Service、问卷 Service 与 `0024` 四个文件；无网络、只读根文件系统、去 capabilities 验证通过。
- OpenPGP 备份 `pnx-backup-20260908T124034Z-daily` 已从全新 PostgreSQL/MinIO 卷恢复 1,419 个对象，未跟踪对象为 0。隔离迁移受众为 `348 → 351 → 351 → 348 → 351`，提交/版本始终为 `49/58`。
- 生产一次升级到 `20260908_0024 (head)` 并新增 3 条受众；固定标签 `direction-assignment-history-20260908` 只替换 Backend/Worker。六服务 healthy、重启 0，OpenAPI 108 条路径，健康入口、匿名 401 与日志门通过。
- 回滚标签指向部署前 Backend/Worker `sha256:d6dca2dc1778…` 与 Frontend `sha256:80dc5b64e94e…`。若新增受众已产生提交，优先前滚，不直接降级删除受众。
- 本次标签上线后，并行通知图片任务以 `announcement-inline-images-20260908` 接续替换应用；运行镜像已确认仍包含本修复全部三个代码标记与 `0024`，当前 Alembic 和受众聚合保持 `0024/351`。

## 原始增量：新激活学生补录开放作业

## 背景与根因

当前作业在发布事务中只把当时已经激活的普通学生写入固定受众快照。运行库的唯一作业于 2026-08-25 发布，当时没有普通学生；现有学生账号于 2026-08-27 才激活，因此该作业受众快照为零，普通学生列表、详情和 Dashboard 均按规则不可见。管理员学生视图的实时预览只用于管理员验收，不能形成真实学生的正式作业归属。

## 必要性与需求影响

- 对应 AUTH-003、HW-002、HW-006：新生完成验证并成为普通学生后，应能看到激活时仍开放且与其当时分类匹配的已发布作业。
- 保留固定受众的核心语义：学生之后修改技术方向不重算历史归属，作业受众编辑也不改变既有快照。
- 初始管理员不写入普通学生快照；已截止、提前关闭、归档和草稿作业不补录。
- 不改变现有 API 请求或响应结构，不补发历史邮件，也不把管理员学生视图写入快照。

## 实施方案

1. 在作业仓储增加“为新激活学生补录当前开放作业”的单一职责方法，复用现有全体/届次兼容/方向 union 与 intersection 匹配规则，并跳过已有快照。
2. 邮箱验证事务确认账号最终角色仍为 `student` 后调用该方法，使账号激活和受众写入原子提交。
3. 新增可回滚数据迁移 `20260827_0010`，为运行库中已激活学生补录仍为 `published`、未过截止时间且匹配的作业；迁移使用专用固定时间标记，降级只删除本次补录行。
4. 增加认证服务、仓储 SQL 和迁移链回归，覆盖后续学生补录、首个管理员不补录、已截止/不匹配/已有快照跳过。
5. 同步产品、页面、API、数据库、测试、决策、变更、基线和任务记录。

## 验收标准

- 当前真实学生进入 `/assignments` 和 Dashboard 均能看到“电控第一次作业”。
- 后续学生验证成功后自动获得激活时仍开放且匹配的作业快照；重复执行不产生重复行。
- 管理员、草稿、关闭/归档/已过截止和不匹配作业不被补录。
- 普通学生仍只能读取正式快照，修改方向不会动态获得或失去历史作业。
- 完整前后端质量门、迁移往返、镜像重建、服务重启和运行态验收通过。

## 回滚

- 应用代码可回退到前一提交。
- Alembic 降级到 `20260827_0009` 时只删除 `0010` 用固定时间标记补录的受众行，不删除发布时原有快照或学生后续提交。
- 若补录学生已经产生正式提交，降级前必须先评估其作业访问影响；默认采用前滚修复，避免形成有提交但无受众的状态。
