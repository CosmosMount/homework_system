# 登录冷却与密码校验修复计划

## 状态

全部完成：注册、验证邮件重发和密码重置申请无应用层持久失败窗口，仅无效登录保留 10 分钟重试窗口；Backend/Worker 已部署，备份、运行态数据保护、健康检查和 Docker socket ACL 撤销均已验收（2026-08-29）。

## 背景与问题本质

用户完成邮箱验证后仍收到统一的“用户名或密码错误”提示；在多次确认凭据后又触发长时间等待。现有登录服务会在查询账号、检查 `active` 状态和执行 Argon2id 密码校验之前，先按过去 15 分钟的失败事件拒绝请求，因此历史失败可以继续阻断随后输入正确密码的已验证账号。

本任务不是删除用户、重置密码或清空安全事件，而是调整认证失败策略：有效账号的正确密码应立即建立 Session；无效密码、未验证、禁用和不存在账号仍使用统一错误，并继续按规范化邮箱和来源 IP 记录，达到既有 5 次/30 次阈值后统一等待 10 分钟。注册、验证邮件重发和密码重置申请不再查询应用层持久计数窗口，但仍记录安全事件；Nginx 的瞬时认证入口限流继续保留。

## 影响需求与范围

- AUTH-004：只有 `active` 账号可登录，Connect 用户名和完整邮箱保持同一账号映射。
- AUTH-009：仅无效登录按规范化邮箱与来源 IP 使用 10 分钟失败窗口；已验证 active 账号的正确密码不被既有失败事件阻断；注册、验证邮件重发和密码重置申请不设置应用层持久失败窗口。
- 后端认证 Service、Argon2id 密码校验回归和登录失败限流测试。
- 认证页面、API、安全、架构、数据库说明、测试策略、ADR、变更记录和任务台账。
- 不改变 API 请求/成功响应结构，不新增依赖，不修改数据库结构，不迁移、删除、清空或重算现有用户密码哈希。

## 实施步骤

1. 先增加可复现测试：构造真实 Argon2id 哈希和已验证 `active` 用户，同时让历史失败计数达到阈值；正确密码必须登录，密码哈希在无需升级时保持不变。
2. 调整登录 Service：先完成规范化账号查询与恒定成本密码校验；只有账号不存在、密码错误或状态不可登录时才应用失败计数与 429，随后记录当前失败事件。
3. 增加对照测试：无效凭据达到邮箱/IP 阈值后仍返回 `RATE_LIMITED` 且 `Retry-After` 为 600 秒，不创建 Session；`pending_email` 和 `disabled` 不因顺序调整绕过状态限制。
4. 增加无持久窗口回归：注册、验证邮件重发和密码重置申请均不查询历史安全事件计数，不因历史事件返回应用层 429；安全事件继续保留用于审计和分析。
5. 同步 AUTH-009、页面、API、安全、架构、数据事件语义、测试矩阵、ADR 和变更记录。
6. 运行认证定向 Pytest、密码安全测试、Ruff、格式检查和严格 Mypy；风险允许时运行完整后端测试。
7. 确认 Alembic head 没有变化、工作树没有用户数据或密码材料，并更新当前任务、完成记录和项目记忆。

## 验证方式

- 正确路径：真实 `PasswordManager` 生成的 Argon2id 哈希可由登录 Service 校验；即使已有失败事件达到阈值，`active` 用户仍创建一个 Session。
- 错误路径：错误密码、未知账号、`pending_email`、`disabled` 继续使用统一 `INVALID_CREDENTIALS`；达到阈值时返回 429 和 `Retry-After: 600`，且响应不泄露账号状态。
- 非登录入口：注册、验证邮件重发和密码重置申请不调用安全事件计数查询，重复请求不产生应用层持久等待；仍写入既有安全事件，不删除历史记录。
- 数据安全：测试断言无需升级参数时 `password_hash` 原值不变；本任务没有 Alembic revision、批量更新、账号删除或安全事件清理。
- 静态与回归：认证定向测试、密码算法测试、Ruff、格式和严格 Mypy 通过；完整测试结果单独记录。

## 风险与控制

- **暴力尝试**：无效登录仍按邮箱/IP 记录并在 10 分钟窗口内返回 429，Nginx 继续使用真实来源 IP 的粗限流；注册、重发和重置申请仅删除应用层持久窗口，不取消安全事件或入口瞬时限速。
- **账号枚举**：不存在、密码错误、待验证和禁用账号仍共享状态码、错误码和文案；不存在账号继续执行 Argon2id dummy 校验。
- **状态绕过**：密码正确但非 `active` 仍视为失败，不能创建 Session。
- **密码数据**：不输出真实哈希或密码，不重置账号，不批量重哈希；仅登录成功且 Argon2 参数确需升级时保留既有透明重哈希行为。
- **运行库核对受限**：当前 Docker socket 权限已按既有运维基线收敛，若无法只读进入运行容器，必须明确区分源码/测试结论与尚未执行的运行库核对，不擅自恢复 Docker ACL。

## 回滚方式

本任务只有应用代码、测试和文档变更，无数据库迁移。回滚对应提交并重新构建 Backend/Worker 即可恢复旧流程；既有用户、密码哈希和安全事件无需恢复。
