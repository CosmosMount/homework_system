# 物资管理移植计划

## 背景与必要性

当前平台没有物资台账，学生无法在本系统通过实物二维码领用和归还。参考仓库 `../management_system` 已有逐件、批量、配套物资、扫码确认、拍照归还、软删除和 D110 标签打印的完整流程。本任务将其行为移植到本项目的学生与管理员 Session、FastAPI、PostgreSQL、MinIO 和 Next.js 分层中，不调用参考系统运行时或共用数据库。

## 需求与影响

- 新增 MAT-001～MAT-008，覆盖台账筛选与数量、1～100 件幂等登记及配套登记、永久二维码、扫码显式领用/归还、8 MiB 图片校验和受保护查看、下一次领用清理旧照片、登记人或真实管理员整套软删除、D110 系列单张与批量标签打印。
- 激活学生可登记和领用；真实管理员可登记、领用与删除任意物资，学生只可删除本人登记且当前无人领用的物资。管理员学生视图按学生权限执行。账号停用后既有 Session 失效。账号注销/自动清理时物资和历史保留并去身份化；若仍有未归还物资，需保留占用状态并允许真实管理员拍照处理匿名遗留占用。
- 新建 `materials`、`material_loans` 表和可回滚 Alembic 迁移。物资照片只存 MinIO，数据库保留服务端生成的对象键及元数据；照片不进入普通作业上传入口。为下一次领用时的旧照片清理复用 PostgreSQL Outbox Worker。
- 修改页面、导航、API 契约、数据库说明、安全规则、测试矩阵、决策与变更记录。保持现有工作区其他未提交改动原样。

## 实施步骤

1. 核对参考实现和本项目身份、对象存储、审计、Worker、账号擦除边界；先更新 API 与数据库设计。
2. 建立模型与可回滚迁移；实现 Repository、Service、Router、图片校验和 Outbox 清理，锁定整套物资并以唯一索引保证并发与幂等。
3. 接入响应式物资台账、登记、详情、扫码页和二维码；复用既有 `qrcode`，按参考系统适配 D110 系列 Web Serial 单张及批量打印。
4. 验证权限、状态、配套原子性、照片生命周期、账号擦除、API 契约、迁移往返与前端交互；更新全部受影响中文文档和任务记录。

## 验证边界

源码与隔离测试可自动执行；真实 D110 硬件和在校实物扫码需上线阶段验证。生产迁移前必须按既有部署要求完成 PostgreSQL/MinIO 同点备份。

## 生产部署（2026-10-16 用户授权）

1. 修复归还照片上传超过 Nginx 默认 2 MiB 限额的问题；备份安全路径、数据库引用对账纳入归还照片，并覆盖配套物资共用照片及等待清理对象的测试。
2. 核对已上线固定镜像与工作区源码差异，从明确的源码快照构建固定 Backend/Worker、Frontend 镜像；在镜像内完成正式编译，验证 Nginx 配置。
3. 暂停生产写入后创建 PostgreSQL 与 MinIO 加密同点备份；在独立空卷 `pnx-restore-*` 项目恢复并零差异对账，在副本上验证 `0030→0031→0030→0031` 和模型漂移。
4. 备份和副本验收通过后，生产执行一次 `0030→0031`，按 Backend/Worker、Frontend/Nginx 顺序切换。检查健康、鉴权、运行 API、空物资台账、请求体限额和近期错误；保留旧镜像用于应用回滚。
5. 更新部署、数据库、测试、变更和运维记录。现有 HTTP 入口不具备浏览器 Web Serial 所需安全上下文，D110 实物打印在 HTTPS 与设备就绪后验收。
