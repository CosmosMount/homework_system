# 阶段 6：生产运维加固与发布收口计划

## 背景与必要性

阶段 1～5 已完成认证、通知、个人作业、校内赛、共享不可变提交、私密评语和 MinIO multipart 的完整业务闭环，并通过真实 Linux Docker、PostgreSQL 迁移往返和局域网 `5000` 端口验收。当前 Compose 仍是开发入口：HTTP 单端口、开发环境变量、缺少可执行备份/恢复/对账工具、未设置生产资源与只读边界，也没有完整的发布候选安全扫描、浏览器端到端和容量报告。

阶段 6 不新增业务角色或产品模块，而是把现有系统收敛为可审查、可部署、可备份、可恢复和可回滚的首版发布候选，对应 NFR-001、NFR-003～NFR-010、NFR-012。生产域名、受信证书、校园 SMTP 和异机备份目标属于部署方外部材料；仓库必须提供强制校验、模板、脚本和隔离演练，不能伪造这些外部凭证已具备。

## 权威依据与影响范围

- 产品与验收：`.agents/docs/01-product-requirements.md` 的 NFR-001～NFR-012，以及 `.agents/docs/11-testing-strategy.md` 的 NFR-T01～NFR-T12。
- 架构与安全：`.agents/docs/05-system-architecture.md`、`08-auth-security-email.md`、`09-file-upload-storage.md`、`15-decisions.md`。
- 部署与恢复：`.agents/docs/10-deployment-network.md` 的 HTTPS、固定镜像、健康、日志、备份、恢复、发布、回滚和容量基线。
- 主要修改范围：`infra/`、`.github/workflows/`、必要的 Backend 运维查询/CLI、前后端端到端测试、根 README 与权威文档；不引入评分、排名、公开页面、消息队列或新的业务角色。

## 现状与可复用能力

- 复用现有非 root 前后端镜像、健康检查、三网络 Compose、Nginx 同源路由和日志轮换。
- 复用 Alembic 单一 head、PostgreSQL/MinIO 持久卷、服务端对象键和 `StoredFile` 元数据做备份恢复后的引用对账。
- 复用 `/health/live`、`/health/ready`、`/health/worker`、结构化请求日志、Outbox 状态和管理员审计。
- 复用现有单元/组件/API 契约与真实 Compose 冒烟，新增生产配置、恢复、浏览器和性能层，不复制已有业务测试。

## 实施步骤

### 1. 生产配置与最小权限 Compose

1. 增加独立生产 Compose overlay 和生产环境模板，只允许固定镜像标签或 digest，不在生产自动 `build`，Nginx 仅发布 80/443。
2. 为 Backend、Worker、Frontend 和 Nginx 设置非 root、`no-new-privileges`、只读根文件系统、必要 `tmpfs`、资源/进程限制、优雅停止和受限 capability；PostgreSQL/MinIO 仅挂载持久数据并保持无主机管理端口。
3. 把应用秘密改为 Docker secrets/file 注入或受控环境文件；扩展 Settings 支持必要的 `*_FILE`，启动时拒绝生产 HTTP、弱默认值、空关键配置和错误校园域名。
4. 增加生产 Nginx 配置：80 永久跳转 443、TLS 1.2/1.3、证书挂载、HSTS/CSP/帧限制等安全头、`/_next` 指纹缓存、API/对象路径既有大小与超时边界。
5. 用临时测试 CA 在隔离端口演练生产配置，验证 Secure `__Host-` Cookie、HTTP→HTTPS、仅 Nginx 暴露以及内部服务不可从主机访问；不把测试私钥提交仓库。

### 2. 备份、恢复与引用对账

1. 在 `infra/backup/` 实现严格 shell 脚本：生成 UTC 时间戳清单、`pg_dump` 自定义格式、MinIO 对象镜像/清单、非秘密配置快照和 SHA-256 清单。
2. 备份输出必须在离开宿主机前使用明确配置的加密接收方加密；缺少加密配置直接失败，不提供明文“成功”路径。日志只记录备份 ID、大小、计数、耗时和错误码。
3. 实现保留策略：14 个每日、8 个每周，先校验命名和目标目录，再只删除已确认的过期备份集合；不对宽泛路径递归删除。
4. 实现隔离恢复脚本：校验清单、恢复 PostgreSQL 与 MinIO、检查 Alembic head，再运行只读引用对账。
5. 增加 Backend 运维 CLI 对账命令，逐个验证 `available` 文件对象存在、大小和 SHA-256，报告数据库缺对象、对象属性不符和未引用对象候选；默认只读，绝不自动删除。
6. 在独立临时 Compose 项目和临时卷完成真实备份→破坏隔离副本→恢复→对账→登录/读取/下载冒烟，记录实际 RPO/RTO；不得修改当前开发数据卷。

### 3. 可观测性与故障演练

1. 增加机器可读运维检查脚本，聚合 HTTPS、Frontend、Backend、Worker、PostgreSQL、MinIO、Outbox oldest/dead、上传失败/孤立和备份新鲜度；敏感结果只返回计数和状态。
2. 为 API/Worker/Nginx 保持结构化日志字段一致，验证请求 ID 贯穿且日志轮换生效；补齐不含 Cookie、令牌、邀请码、私密评语和文件名的检查。
3. 提供独立告警规则/示例配置，覆盖证书 30 天、Worker 5 分钟、Outbox 10 分钟/dead、数据库、对象存储、备份 24 小时、磁盘 20%/10%、5xx 与 P95；通知目标由部署方注入且不依赖本系统自身邮件。
4. 在隔离 Compose 中逐一停止 Frontend、Backend、Worker、PostgreSQL 和 MinIO，验证对应健康/用户影响与恢复；当前局域网开发服务不用于破坏性故障注入。

### 4. 发布、回滚与 CI 安全门

1. 增加发布前检查、部署和回滚脚本/手册：固定镜像、配置校验、备份门、迁移、滚动启动、健康等待、冒烟、观察和回退；数据库降级只允许已测试路径，写入发生后禁止盲目恢复旧备份。
2. CI 增加 Dockerfile/Compose 静态检查、生产配置渲染、秘密扫描、SBOM、依赖与镜像高危漏洞扫描；工具版本固定，扫描失败不能静默跳过。
3. 增加 Playwright 核心路径：学生注册/登录、通知/作业、赛事组队和管理员管理；浏览器矩阵至少在发布候选覆盖 Chromium、Firefox、WebKit，测试数据完全虚构。
4. 增加迁移从空库及阶段 5 代表数据升级/降级验证；当前阶段若无新业务结构，不为了“有迁移”新增空迁移。

### 5. 容量、性能与无障碍验收

1. 提供确定性虚构数据生成器，目标为 300 学生、10 管理员、100 通知、40 作业、10 赛事和 100 历史队伍；种子命名与清理范围明确。
2. 增加可重复运行的读取负载脚本，100 并发浏览会话覆盖工作台、通知、作业和赛事，输出吞吐、错误率和 P50/P95/P99；非上传 API P95 < 500 ms、错误率 < 1%。
3. 增加 20 并发 multipart 的可缩放演练模式，CI 使用小文件验证协议，容量环境使用稀疏/流式 100 MiB 与近 2 GiB 样本，不把大文件写入仓库或进程内存。
4. 运行 360/768/1280/1440 响应式、键盘、焦点、`aria-live`、对比度和 reduced-motion 检查，记录浏览器与未覆盖项。
5. 根据实测 CPU、内存、PostgreSQL 连接、MinIO 容量和 Nginx 并发更新资源限制与容量报告，不凭假设填写生产数值。

### 6. 文档、最终验收与交付

1. 更新部署、上传、安全、测试、路线图、ADR、变更记录、README、项目基线和任务台账；新增发布/回滚、备份/恢复、监控告警和容量报告均放入 `.agents/docs/`。
2. 运行前后端完整质量门、迁移、生产镜像、生产配置、HTTPS、备份恢复、对账、故障、浏览器、秘密/漏洞和性能验收。
3. 保持现有开发服务继续通过 `http://10.4.150.222:5000` 可访问；生产演练使用独立 Compose project、临时端口和临时卷，完成后安全清理。
4. 明确记录外部遗留项：受信生产域名/证书、校园 SMTP、异机加密备份目标和独立告警接收方只有部署方提供后才能做现场最终验收。

## 风险与控制

- **备份假成功**：脚本对每一步 `set -Eeuo pipefail`，校验退出码、非空产物、哈希和对象计数；没有加密接收方即失败。
- **恢复污染当前数据**：恢复只接受显式临时项目名、目标目录和空目标卷；禁止默认指向当前 Compose project 或宽泛路径。
- **生产配置破坏开发入口**：保留现有开发 Compose 和 `5000` 环境不变，生产能力通过 overlay/独立配置增加。
- **只读根文件系统导致运行失败**：逐服务列出必要 `tmpfs` 与挂载，先在隔离生产演练中验证，不开放过宽写目录。
- **性能数字失真**：报告记录机器、数据集、并发、持续时间、样本数和命令；CI 小样本不冒充容量验收。
- **扫描供应链漂移**：固定扫描工具版本并保存机器可读结果；网络不可用时明确标记阻塞，不能把未执行写成通过。

## 完成标准

- 生产 Compose 只暴露 Nginx 80/443，HTTPS、Secure Cookie、固定镜像、最小权限、资源限制和强配置校验通过隔离演练。
- 加密备份、保留、隔离恢复和数据库/MinIO 引用对账工具可重复运行，恢复后的核心业务冒烟通过并记录 RPO/RTO。
- 健康、日志、告警规则、发布/回滚手册和故障演练覆盖全部运行组件，不泄露秘密。
- CI 包含完整质量门、生产配置、Playwright、秘密/SBOM/依赖/镜像扫描；没有未解释的高危结果。
- 基准数据集性能达到非上传 API P95 < 500 ms、错误率 < 1%，并形成可复查容量报告。
- 权威文档与任务台账收口，已实现的完整系统继续可从局域网 `http://10.4.150.222:5000` 使用；外部生产材料的现场验收项被明确列出而非伪造完成。
