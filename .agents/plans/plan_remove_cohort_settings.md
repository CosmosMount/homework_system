# 删除届次设置

## 背景

当前管理员侧栏、用户管理、个人资料以及通知/作业受众表单仍暴露“届次”配置。产品已不再需要按届次维护账号或新建内容受众，继续展示会造成管理员误解，也会让发布流程依赖一个不再维护的分类。

## 范围与取舍

- 删除管理员导航中的届次设置入口及届次创建/启停界面，保留同页的技术方向管理。
- 用户管理和个人资料不再展示或编辑届次；用户仍可按技术方向管理。
- 通知和作业新建/编辑界面改为“全部学生”或“按技术方向”，新请求始终发送空的 `cohort_ids`。
- 已有历史资源中的届次受众字段继续由后端和数据库保留并在编辑保存时原样兼容，避免未经确认的数据清理或历史通知/作业失效；不新增破坏性迁移。
- 后端旧 `/admin/cohorts` API、模型和关联表暂保留为兼容路径，不再作为产品入口。后续若要彻底删除数据结构，另行设计备份、迁移和回滚方案。

## 影响

- 前端页面、导航、表单文案和回归测试。
- 产品、信息架构、API、数据库、测试和变更文档需要说明“方向是当前唯一可维护分类，届次仅历史兼容”。
- 无数据库结构变更、无数据删除、无权限边界变化。

## 验证

- 前端测试、ESLint、严格 TypeScript 和生产构建。
- 检查管理员侧栏与用户/资料页面不出现届次设置；新建通知/作业仍可按方向发布且请求携带空 `cohort_ids`。
- 后端现有完整测试、Ruff、格式和严格 Mypy，确认兼容 API 与历史受众逻辑未回归。
- 修改后自动重建并重启 Compose 服务，验收健康端点和 5000 端口。
