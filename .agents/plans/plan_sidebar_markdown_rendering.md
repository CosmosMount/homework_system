# 侧边栏导航与统一 Markdown 展示计划

## 背景

当前登录后的所有页面共用顶部横向导航，管理端作业编辑页同时展示 Markdown 文本框和一个带内部实现标签的“渲染预览”卡片。用户希望把导航切换为侧边栏，并明确编辑与阅读边界：只有 Markdown 编辑界面显示编辑器，其他界面直接展示渲染后的安全内容；管理员与学生使用同一套渲染结果和样式。

## 必要性

- 侧边栏能容纳管理员和学生不同数量的入口，减少顶部导航拥挤，并为当前页面提供稳定的 active 状态。
- “Markdown 渲染预览”“已清洗 HTML”是实现细节，不应作为用户界面文案出现。

## 修改范围

- 将 `AppShell` 的顶部横向导航改为响应式侧边栏：桌面端支持收起/展开，窄屏提供侧边抽屉入口；学生和管理员共享同一布局与导航链接。
- 保留管理员/学生现有路由和后端权限，不通过前端侧边栏承担授权。
- 将 Markdown 编辑器保留在管理员通知、作业、赛事/赛题和提交评语等编辑场景；阅读详情继续只渲染服务端返回的安全 HTML。
- 重构编辑器中的渲染区为无内部标签的统一文档展示，删除“Markdown 渲染预览”“已清洗 HTML”等字样，并让管理员编辑页展示与用户详情页相同的 `SafeHtml` 内容样式。
- 补充侧边栏、active 状态、移动端入口、统一渲染和不出现内部文案的前端回归测试；同步设计系统、页面说明、测试策略、变更记录和任务记录。

## 验证方式

- 前端 Vitest、ESLint、严格 TypeScript、Next.js 生产构建。
- 检查管理员与学生导航均为侧边栏语义，active 链接可识别，窄屏可打开/关闭导航。
- 检查编辑界面可见 Markdown 文本框，详情/预览界面不出现 Markdown 源文或内部实现标签，管理员和学生使用相同 `SafeHtml` 渲染结构。
- 不修改后端 API、权限规则、数据库结构、迁移和业务数据。

## 本次执行结果（2026-08-26）

- `AppShell` 已改为共享响应式侧边栏：桌面端可折叠，移动端可打开抽屉，管理员与学生沿用各自权限范围内的入口和 active 状态。
- Markdown 编辑器保留源文本框；管理员通知、作业编辑中的已保存内容使用共享 `RenderedMarkdown`/`SafeHtml` 输出，用户详情继续使用同一 `SafeHtml` 管线，不显示内部实现标签。
- 前端 14 个测试文件、43 项测试、ESLint、严格 TypeScript 和 Next.js 生产构建全部通过；未修改后端 API、权限、数据库结构或迁移。
