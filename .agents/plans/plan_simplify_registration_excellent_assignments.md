# 简化注册与优秀作业展示计划

## 问题背景

现有设计要求学生验证邮箱后等待管理员审核并分配届次、技术方向，同时把优秀成果设计为独立的范本内容域。项目负责人现确认首版应更简单：只要邮箱后缀为 `hkust-gz.edu.cn`，完成邮箱验证后即可登录；优秀成果只在对应作业页面显示为“优秀作业”。

## 现有结构分析

- 认证文档当前包含 `pending_review`、`rejected`、注册审核页面、审核 API、审核邮件和届次/方向必填约束。
- 届次和方向同时承担定向通知/作业的可选受众维度。此次变更只取消注册时强制审核和分组，不删除后续可选分类能力。
- 优秀范本当前拥有独立列表、详情、管理路由、API、状态机、数据表和赛事来源，超出“作业内显示优秀作业”的实际需求。
- 仓库目前只有设计文档，没有业务源码和迁移，因此可以直接更新权威基线，无兼容数据迁移成本。

## 计划修改

1. 将账号状态收缩为 `pending_email`、`active`、`disabled`；验证精确后缀 `@hkust-gz.edu.cn` 后直接激活。
2. 删除管理员注册审核、批准、拒绝、审核等待页面/API/邮件；保留管理员禁用、恢复、角色和可选届次/方向维护。
3. 明确未分组用户仍能登录并接收全体内容；只有定向内容需要管理员事后补充分组。
4. 删除独立优秀范本导航、路由、API、状态和赛事范本能力。
5. 将优秀成果改为作业详情中的“优秀作业”：管理员标记某个不可变作业版本，作业受众可查看，私密评语不展示，可随时取消标记。
6. 用 `assignment_excellent_submissions` 关联表替代 `showcases` 与 `showcase_files`，并同步文件删除保护、权限和测试。
7. 更新 README、AGENTS、项目记忆、任务、需求追溯、ADR、路线图和变更记录。

## 涉及模块

- 产品与页面：认证、用户管理、作业详情、管理员提交页、导航。
- 接口与数据：认证 API、用户管理 API、作业优秀版本 API、用户状态和优秀作业关联表。
- 安全与邮件：邮箱域名、验证后激活、Session、通知邮件类型。
- 测试与运维：注册流程、无审核登录、可选分组、优秀作业权限和删除保护。

## 潜在影响

- 任何拥有目标邮箱域名的人都可在验证后进入系统，首版依靠邮箱控制成员范围；管理员仍可事后禁用异常账号。
- 未分配届次/方向的用户无法命中仅按这些维度投放的内容，因此全体新生必需内容应使用“全部学生”受众。
- 优秀作业不再接受赛事提交来源，也没有草稿/发布/撤回状态；标记即在对应作业内可见，取消标记即隐藏。
- 源提交仍不可变；被标记为优秀的版本及附件在取消标记前不能删除。

## 验证方式

- 检查全文不存在 `pending_review`、`rejected`、注册审核路由/API 和独立 `/showcases` 路由。
- 检查 `hkust-gz.edu.cn` 在需求、API、安全、部署和测试中一致。
- 检查优秀作业只关联作业提交版本，不允许赛事版本，且只在作业路由下访问。
- 重新运行 Markdown 链接、代码围栏、需求追溯、测试映射和未决标记检查。

## 完成标准

- 所有权威文档采用相同的简化认证状态机与优秀作业模型。
- 后续 Agent 无需兼容已删除的审核和独立范本设计。
- 不创建业务源码、迁移或部署配置。
