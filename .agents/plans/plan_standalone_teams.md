# 独立队伍域改造计划

## 背景与必要性

原“校内赛”以 competitions 为根实体，队伍创建、报名、阶段和历史赛事提交均依附赛事。当前目标改为保留“校内赛”导航和页面，但产品只支持、展示和管理独立队伍：学生无需等待管理员创建赛事，现有赛事队伍全部退出新产品视图，之后直接创建或加入新队伍。

本任务废止现行 COMP-001～COMP-006，重写 TEAM-001～TEAM-009 为全局独立队伍语义。旧赛事、旧队伍及历史赛事提交属于迁移兼容数据，不再由运行时 API、页面或 Worker 读取。

## 产品与安全决策

- 保留 /competitions、/admin/competitions 及“校内赛”导航名称，页面只展示队伍，不渲染赛事实体，也不提供赛事创建、公告、报名、阶段、赛题或作品入口。
- 激活学生可直接创建队伍、凭邀请码加入或主动自动分配；同一学生全局最多属于一支当前队伍。
- 队伍自身保存 max_members，状态只保留 forming/dissolved。队长可轮换邀请码、移除成员、转让队长；非队长可退出；仅剩队长一人时可解散。
- 公开目录只返回名称、状态、当前/最大人数和能否加入，不公开成员身份或邀请码。
- 邀请码只保存带服务端 pepper 的 HMAC；明文仅在创建、自动建队或轮换成功响应出现一次。
- 真实管理员可带原因补录、移除、转让队长或物理删除独立队伍；不再提供资格取消、人数豁免、锁队或赛事报名纠错。

## 数据迁移

新增接在 20260904_0019 后的 20260904_0020：

1. 将原 teams/team_members 连同原约束和索引重命名为 legacy_competition_teams/legacy_competition_team_members。
2. 新建空的独立 teams/team_members。因此旧队伍在产品语义上全部解散且不会显示，但历史记录没有被物理销毁。
3. 原 competitions、competition_registrations、competition_tasks、历史赛事提交及附件元数据原位保留；运行时不再访问，MinIO 对象不删除。
4. Alembic 只精确排除上述已知 legacy 表以及 submissions 上已知的历史赛事外键、检查和索引；历史提交列仍在 ORM 元数据中声明为内部兼容字段，避免掩盖其他模型漂移。
5. downgrade 先把新独立队伍以带 UUID 的可辨识名称挂到占位赛事，再删除新表、恢复旧表名和触发器；因此新旧队伍都可保留。再次 upgrade 后它们全部回到 legacy 表，新产品表重新为空。

## 后端改造

- 用 teams 模块替换赛事模块；Router 只暴露 /teams* 和 /admin/teams*。
- 创建、加入、自动分配使用队伍/成员行锁与“每人全局一支当前队伍”部分唯一索引处理并发。
- 自动分配优先选择人数最少、创建时间最早的未满 forming 队伍，无候选时创建队伍。
- 工作台只返回本人 team，通知分类键改为 teams。
- 作业提交、上传、评语、下载授权、账号擦除和 Worker 不再提供赛事运行路径；提交 Repository 始终过滤 assignment_id IS NOT NULL。

## 前端改造

- /competitions 直接加载本人队伍与公开目录；无队伍时显示创建、邀请码加入和自动分配，有队伍时显示成员与队长管理。
- /admin/competitions 直接加载独立队伍目录；/admin/competitions/[teamId] 作为队伍纠错详情。
- 旧学生赛事详情/队伍/赛题路由重定向 /competitions；旧管理员嵌套队伍路由重定向新队伍详情，/admin/competitions/new 重定向管理目录。
- 删除赛事编辑、报名管理和旧报名操作组件；个人作业提交与管理员审阅只保留作业语义。

## 文档与追溯

- 新增 ADR-059，定向替代 ADR-023、ADR-026、ADR-027 和 ADR-044 的现行赛事/依附队伍部分。
- 同步项目概览、产品需求、信息架构、页面、架构、API、数据库、安全、测试、路线图、变更记录、项目基线与任务记录。
- 历史变更与历史 ADR 原文保留，用“被替代”关系维持追溯，不把过去已经发生的部署记录改写成当前状态。

## 验证方式

- 前端：ESLint、严格 TypeScript、完整 Vitest、Next.js 生产构建。
- 后端：完整 Pytest、Ruff、格式检查、严格 Mypy。
- 迁移：离线 SQL；隔离 PostgreSQL 0019 → 0020 → 0019 → 0020；带虚构旧队伍和新队伍验证 legacy/空产品表；两次 alembic check。
- 最终：OpenAPI 运行路径扫描、全仓赛事残留分类、git diff --check。允许历史迁移、被替代 ADR、legacy 元数据和兼容重定向出现 competition，当前 API 与业务实现不得依赖赛事实体。

## 回滚与风险

- 升级本身不删除旧赛事、旧队伍、历史赛事提交或 MinIO 对象；数据库降级可以保留新独立队伍，但队名会附加稳定 UUID 标识以规避与既有占位赛事队伍冲突。
- 旧数据仅由数据库兼容结构保留，不提供产品读取入口。若未来需要查阅，必须另立需求和权限设计，不能重新接回当前运行 API。
- 本任务只修改源码、迁移、测试和权威文档；不连接或修改当前运行 PostgreSQL/MinIO，不构建镜像、不部署。
