# 学生校内赛组队与意向调查计划

## 背景

学生赛事入口目前仍按“赛事列表”组织，单一校内赛产品约束下需要直接成为队伍中心；同时平台缺少用于收集学生方向/参与意向的调查能力和移动端填写入口。

2026-08-28 运行态回归发现管理员创建带选项的调查时返回 500：父调查和选项同时进入 SQLAlchemy Session，但 ORM 未建立可保证插入顺序的关系依赖，实际先插入选项并触发 `intention_options.survey_id` 外键失败。本计划继续作为该意向调查域的唯一正式计划，追加最小持久化顺序修复，不新建重复计划。

2026-08-28 用户进一步要求把单题“意向调查”升级为多题问卷：管理员可设置“第一志愿、第二志愿”等多个单选/多选题，查看实名提交名单，并限制每名学生的提交次数。本计划继续作为该领域唯一正式计划，追加问卷升级，不创建第二份计划。

## 目标与决策

- 学生 `/competitions` 只展示当前未归档校内赛公告摘要、我的队伍状态和可加入队伍目录；队伍目录支持名称搜索，只返回仍在成形且未满的公开摘要。
- 保留现有邀请码加入流程，并增加“没有队伍？自动分配”：仅报名期、已报名且无队伍的学生可以主动申请；事务锁住赛事和候选队伍，优先加入人数较少的成形队伍，没有可用队伍时创建系统生成队伍，继续由一赛一队唯一索引兜底并写审计。
- 新增独立意向调查域：管理员创建调查和单选/多选选项，开放/关闭调查；学生登录后填写或修改自己的回答；管理员只看到汇总人数和比例，不向学生公开他人回答。
- 管理员可生成调查填写二维码。二维码定位地址使用不可猜测的调查 token，但填写页仍要求登录，token 只定位调查，不作为身份凭证；不新增匿名改答流程。
- 用户界面统一使用“问卷”；已有 `/intentions` 路由、数据库表前缀和内部模块名继续作为兼容标识，避免破坏历史二维码与链接。
- 一份问卷包含 1～30 个必答选择题，每题独立配置单选或多选及 1～30 个选项；“第一志愿”“第二志愿”等是独立题目，不把优先级编码进选项或固定用户字段。
- 问卷可配置每人最多提交次数，留空表示不限；每次成功保存当前答案消耗一次，达到上限后服务端拒绝再次提交。管理员名单展示提交人姓名、学号、邮箱、最新答案、累计提交次数和最后提交时间，不向学生公开他人答案。
- 已有单题调查迁移为只含一个问题的问卷，原选项和回答关系保持不变；原回答修订次数初始化为已提交次数，已有调查默认不限次数，避免升级后阻止原有改答流程。

## 回滚

回滚代码和 `0009` 迁移即可恢复原学生赛事列表；调查数据表不影响既有赛事、通知和作业数据。二维码 token 仅用于定位调查，失效后不影响账号或其他业务。

问卷升级可将 `0013` 降级到 `0012`：迁移先恢复旧 `allow_multiple` 和 `survey_id` 字段，再按题目顺序展平选项并删除问题/次数列，原选择关联仍保留。由于旧结构无法表达题目标题、分题规则和提交上限，生产降级属于有损语义回滚，必须先完成 PostgreSQL 备份；代码回退后继续使用原 `/intentions` 路径。
