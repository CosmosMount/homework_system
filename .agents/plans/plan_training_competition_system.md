# 新生培训作业与校内赛系统文档建设计划

> 变更说明：本计划最初记录的“管理员注册审核、强制初始分组、独立优秀范本”已由 `plan_simplify_registration_excellent_assignments.md` 及 ADR-013、ADR-016 替代；其余文档基线建设范围继续有效。

## 问题背景

当前仓库尚无源码和项目文档。团队已有独立的官网与飞书培训知识库，但缺少用于账号审核、内部通知、培训作业提交、私密评语、校内赛组队与作品展示的动态业务系统。若直接开始编码，后续 Agent 容易重复推断需求，并造成页面、接口、数据库和权限实现不一致。

## 现有结构分析

- 本仓库为空仓库，适合从权威文档开始建立项目基线。
- 现有官网是独立的 Next.js 静态站，培训内容由飞书同步生成，不纳入本仓库，也不在首版进行接口集成。
- 项目根目录的入口文档只承担导航职责；详细设计与任务记录统一存放在 `.agents/` 下。
- 首个里程碑不初始化前后端项目，不生成迁移或部署文件，只完成可以直接指导后续实现的中文设计文档。

## 计划修改内容

1. 创建根目录 `README.md` 和 `AGENTS.md`，定义项目入口、必读顺序和 Agent 工作边界。
2. 在 `.agents/docs/` 中建立产品、页面、架构、API、数据库、安全、上传、部署、测试和工程规范文档。
3. 在 `.agents/tasks/` 中维护当前任务、待办和已完成记录，在 `.agents/memories/` 中保存项目基线记忆。
4. 使用稳定的需求编号、状态枚举、角色权限矩阵和统一术语，使需求能够追溯到页面、API、数据实体和测试场景。
5. 明确首版不包含多租户、校园 SSO、课程内容管理、评分排名、公开访客页面和现有官网集成。

## 涉及模块

- 产品：账号审核、通知、个人作业、团队赛事、私密评语、优秀范本。
- 体验：信息架构、路由、PNX 深色设计系统、响应式和无障碍状态。
- 技术：Next.js、FastAPI、PostgreSQL、MinIO、Nginx、Docker Compose、SMTP Outbox Worker。
- 安全与运维：Session、CSRF、Argon2id、上传校验、审计、备份恢复和内网 HTTPS。

## 潜在影响

- 后续实现必须以本批文档为权威来源，接口或数据结构变化需要同步更新文档和决策记录。
- 两类提交共用版本模型，但作业只能由个人提交，赛事只能由队伍提交；这是权限和数据库约束的核心边界。
- 2 GB 版本附件上限要求使用对象存储分片直传，不能由 FastAPI 进程中转整个文件。
- 邮件属于可靠异步任务，需要数据库 Outbox 和独立 Worker，不能只依赖请求内后台任务。

## 验证方式

- 检查全部 Markdown 链接目标存在，README 与 AGENTS 索引一致。
- 检查需求编号在需求、页面、API、数据库映射和测试场景中均有引用。
- 检查角色、状态机、时间边界、提交所有者和错误码在各文档中一致。
- 搜索临时占位和未决设计标记，确保正式文档中的方案均已确定。
- 检查 Mermaid 代码块闭合，并人工核对架构图、路由图、ER 图和状态机含义。

## 完成标准

- 计划中列出的根目录入口和 `.agents/` 文档全部存在且使用中文。
- 后续工程 Agent 无需从聊天记录补充产品或技术决策即可开始基础设施与认证阶段。
- 本里程碑不包含任何业务源码、依赖清单或运行时配置。

## 执行结果

- 2026-08-23 完成根入口、17 份权威设计文档、任务记录和项目基线记忆。
- 共定义 75 个产品与非功能需求编号，并建立页面、API、数据实体和测试场景的集中追溯矩阵。
- 最终自动检查确认 24 份 Markdown 的本地链接、代码围栏、中文内容、编号文档、需求追溯和测试映射均无问题。
- 按计划未生成业务源码、数据库迁移、依赖清单或部署配置。
