# 邮箱前缀用户名登录与待验证提示计划

## 状态

已完成（2026-08-25）。

## 背景与问题本质

当前登录接口只按完整邮箱查询，登录表单也强制使用 `type=email`。用户希望把 Connect 邮箱 `@` 前的部分自动作为用户名，并支持用户名或完整邮箱登录。

同时，当前开发库存在一个新注册的 Connect 账号处于 `pending_email`，验证邮件任务因开发环境仍使用占位 SMTP 而处于 `retry`。依据 AUTH-004、AUTH-009，待验证账号即使密码正确也必须统一返回登录失败，不能通过用户名登录绕过邮箱验证。本次需要同时改善登录标识和页面解释，但不降低验证边界。

## 需求与影响

- 修改 AUTH-001：Connect 邮箱前缀自动成为派生用户名，不允许独立设置或修改另一套用户名。
- 修改 AUTH-004、AUTH-009：`active` Connect 账号可使用邮箱前缀用户名或完整邮箱登录；旧域名存量账号继续使用完整邮箱。所有形式先规范化为账号邮箱，再执行统一限流、密码校验与状态校验。
- 登录 API 主字段改为 `identifier`，并暂时接受原 `email` 字段作为兼容输入；响应和 Session 结构不变。
- 登录失败仍对账号不存在、密码错误、待验证和禁用返回统一错误，不暴露账号状态。
- 注册成功页展示由邮箱派生的用户名，并明确邮箱验证完成前不能登录；重发验证仍只接受完整邮箱。

## 设计取舍

1. 用户名不新增数据库列，始终由规范化 Connect 邮箱 local-part 派生。用户名输入 `alice` 在服务端规范化为 `alice@connect.hkust-gz.edu.cn`，避免用户名与邮箱漂移、额外迁移和重复唯一约束。
2. 包含 `@` 的标识按完整邮箱处理，因此旧域名存量账号仍可登录；不为旧域名账号启用前缀用户名，避免旧域名与 Connect 同前缀时产生歧义。
3. 限流和安全事件继续使用规范化后的完整邮箱维度，不把用户名字符串引入 `auth_security_events.email_normalized`。
4. 兼容字段只用于请求解析，前端与新 OpenAPI 契约统一发送 `identifier`；后续若确认没有旧客户端再单独移除 `email` 兼容入口。
5. 不增加公开验证令牌查看、管理员代验证或未验证登录路径。开发环境真实收信问题必须通过注入校园 SMTP 凭证解决。

## 实现步骤

1. 在安全工具中增加登录标识规范化函数，并覆盖大小写、空白、用户名、Connect 全邮箱和旧域名全邮箱。
2. 更新登录 schema、Router、Service，使用户名和完整邮箱共用原密码、状态、限流与 Session 流程。
3. 更新登录表单为“用户名或校园邮箱”，发送 `identifier`；注册成功页显示派生用户名并强调先验证邮箱。
4. 更新认证 E2E 选择器、后端/前端测试和 OpenAPI 契约测试。
5. 同步产品、页面、API、数据库、安全、测试、ADR、变更记录、README、项目记忆和任务台账。
6. 运行完整质量门，重建 Backend/Worker/Frontend/Nginx，通过隔离 active Connect 账号验证用户名与完整邮箱均可登录，再复验局域网 `5000`。

## 验证方式

- 后端：用户名规范化、旧 `email` 请求兼容、OpenAPI `identifier`、完整邮箱/用户名登录、错误统一和限流维度测试。
- 前端：字段语义、自动完成、用户名请求体、完整邮箱请求体兼容、注册成功用户名与验证提示。
- 运行态：不读取或输出真实密码/令牌；使用隔离虚构 active Connect 账号分别以用户名和完整邮箱登录，随后清理测试资源。
- 账号状态：确认当前真实待验证账号仍不能登录，重发邮件继续进入 Outbox，不伪造已投递。

## 风险与控制

- **绕过验证**：用户名只改变查询键，`user.status == active` 条件不变。
- **账号枚举**：登录响应继续统一，页面不根据登录失败显示待验证状态。
- **旧域名冲突**：旧域名只支持完整邮箱，Connect 用户名固定补 Connect 后缀。
- **限流绕过**：用户名和对应 Connect 全邮箱规范化为同一完整邮箱，合并计数。
- **SMTP 不可用**：代码不能替代部署凭证；最终明确报告当前邮件仍重试和所需外部材料。

## 完成标准

- Connect 激活账号可用邮箱前缀或完整邮箱登录，两种方式建立相同账号 Session。
- 旧请求的 `email` 字段仍可用，新前端和 OpenAPI 使用 `identifier`。
- 待验证/禁用/不存在/密码错误保持统一失败，用户名不能绕过验证。
- 注册成功页明确展示用户名和验证前不可登录。
- 文档、测试、Docker 运行态和局域网 `5000` 验收一致。
