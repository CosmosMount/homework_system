# 纯白背景与整体 UI 优化计划

## 背景

当前前端仍以浅蓝网格和径向渐变作为页面背景，内容卡片、侧栏和认证页虽然使用了蓝白令牌，但层次较分散。用户希望背景改为纯白，并让整体界面更简洁、统一、易读。

## 目标与必要性

- 页面主背景统一为纯白，避免网格/渐变干扰通知、作业和 Markdown 内容阅读。
- 保留蓝白品牌识别，以浅蓝作为交互和选中状态，以深蓝保证文字与焦点对比度。
- 统一卡片、侧栏、表单和按钮的圆角、边框、阴影与悬停反馈，改善桌面与移动端的视觉层级。
- 复用现有 CSS 令牌和布局组件，不引入新依赖，不改变权限、API、数据库或业务流程。

## 修改范围

1. 调整 `frontend/app/globals.css` 的颜色、背景和基础控件令牌：`body`/`html` 使用纯白背景，表面和边框使用更清晰的蓝灰层次，补充统一的控件过渡与阴影。
2. 优化 `AppShell`、侧边栏、认证壳层和管理员页头的表面、边框、间距和阴影，使其在纯白背景上仍有明确层级。
3. 通过共享表单控件类改善输入框、次要按钮和提示区域的焦点/悬停状态；保留现有浅蓝主按钮和无障碍焦点环。
4. 增加轻量的前端回归断言，确认纯白背景令牌和共享布局类不回退到渐变背景。

## 影响与不修改范围

- 对应页面与非功能需求：全局登录后布局、认证页面、通知、作业、赛事及 NFR-004、NFR-011。
- 不修改服务端清洗 Markdown 的路径，不新增 Markdown 解析器；不修改业务 API、权限、数据库迁移或部署拓扑。
- 纯白背景不移除内容区域必要的浅蓝 hover/提示底色，确保状态和交互仍可辨识。

## 验证与上线

1. 运行前端 Vitest、ESLint、严格 TypeScript 和 Next.js 生产构建。
2. 检查主要页面在 1280px 桌面和移动宽度下的纯白背景、侧栏、卡片、表单与焦点状态。
3. 按既定流程重建并替换 Frontend，重启 Frontend/Nginx，确认 Compose 健康检查与 5000 端口可访问。
4. 更新 `.agents/tasks/current-task.md`、`.agents/tasks/completed.md`（如存在对应记录）、设计/变更文档和项目基线。
